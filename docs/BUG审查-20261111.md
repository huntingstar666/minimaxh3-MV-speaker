## P1（会导致成片时长/音画错误或功能点了不生效）

### P1-1 MV mixed 在 25/30fps 下成片被截短（音轨一起被截）

- 位置：
  - `backend/jobs.py:1535`（mixed 生成完成后拼接）
  - `backend/jobs.py:1633`（mixed「重新合成成片」）
  - `backend/jobs.py:1318`（缺逐窗节点时的 seam 回退）
- 现象：`media.concat(clips, ..., total_edit, work)` 没有传 `fps`，使用默认 `24`。
  - 链路文件已在 `backend/jobs.py:1512` 用 `media.normalize(..., fps=fps)` 转成 25/30fps；
  - 拼接时 `media.concat` 按 24fps 计算输出帧数与 `-t`，`-frames:v` 会把 30fps 成片裁到 `总帧数`（而不是 `总帧数 × 30/24`）。
- 影响：30fps mixed 成片只剩约 80% 时长，尾部台词/画面被截掉；25fps 约少 4%。音频也被 `-t` 同步截断。
- 验证：
  ```
  total_edit = 1000 (24fps 口径)
  media.output_frame_count(1000, 30) = 1250   # 应有
  media.output_frame_count(1000)      = 1000   # mixed 实际
  应有 41.67s，实际 33.33s
  ```
- 建议：三处都补 `fps=fps`（mixed 的 `fps` 已在 `backend/jobs.py:1397` 解析好），并让 `final.output_frames` 用同一口径。
- 备注：全局逐窗 seam（`backend/jobs.py:1215`）和普通硬切（`backend/jobs.py:1702`）都传了 `fps`，只有 mixed / legacy seam 漏了。

### P1-2 数字人「开始生成」不会重跑已完成段，且日志里提到的「全部重新生成」在界面上不存在

- 位置：
  - `backend/avatar/job.py:661-666`（模式 1）与 `backend/avatar/job.py:525-530`（模式 2/3）都只在 `status != completed` 或缺少 `selected_take` 时生成；
  - `web/avatar/js/avatar.js:5743` 固定 `force: false`；
  - `web/avatar/index.html` 只有 `#btn-generate`，没有「全部重新生成 / 强制重跑」入口。
- 现象：
  - 项目所有段都生成过一次后，改模型 / 步数 / 种子 / 提示词，再点「开始生成」，`targets` 为空，任务只做拼接；
  - 模式 1 从硬切切到「首尾帧锚定」、模式 2/3 切到「尾帧接力」后，点「开始生成」同样不会重跑已完成段；
  - 日志提示「可勾选“全部重新生成”」，但页面没有这个控件；前端也从未发送 `force: true`。
- 影响：用户以为改了参数在重跑，实际拿到的是旧片段的重新拼接；锚定/尾帧接力设置不生效。
- 建议：在「开始生成」旁提供「全部重新生成」并发送 `force: "all"` 或索引数组；或在检测到 generation/stitch 变化时自动把已完成段加入 force。
- 备注：纯 seam / mixed 走 `_run_seam`，不受该逻辑影响（会按窗口指纹自动重跑），所以问题集中在 hard / relay / anchor。

### P1-3 数字人「单段重跑」不读取当前表单参数

- 位置：
  - `web/avatar/js/avatar.js:5772`：`api.regenerate(p.id, index)` 没有传 `generation`
  - `backend/avatar/app.py:1828-1837`：仅在 payload 带 generation 时才会用到新参数，且不回写项目
- 现象：右栏改了种子 / 步数 / 模型 / 段间模式后，未点「保存设定」直接点某段「单段重跑」，后端仍按 `project.json` 里的旧参数跑。
- 影响：单段重跑结果与界面参数不一致；用户很难判断是模型问题还是参数没生效。
- 对比：MV 的 `web/js/app.js:1164` 单段重跑会带 `{ generation: collectGeneration() }`，数字人侧漏了。
- 建议：`regenerate` 请求带上 `readGeneration()`；或重跑前先走一次 `PATCH /projects/{id}` 保存。

- 位置：

  - 后端 `backend/avatar/job.py:71-79` 对模式 1 的 5 会强制解释为 22。
- 影响：
  - mixed 模式选 22 / 39 帧，保存的仍是旧值（模式 2/3 默认 5），生成窗口与 UI 不一致；

### P2-2 从「首尾帧锚定」切回硬切后，旧的锚定模板仍被当成 Ref2VA 提示词使用

- 位置：
  - `backend/avatar/app.py:314-326`：只在 `stitch=anchor` 时写入模板；切走时没有清理或标记；
  - `backend/avatar/job.py:830-834`：硬切生成时只要 `row.prompt` 非空就直接使用。
- 现象：锚定项目生成过一轮后切回硬切，每段的 `prompt_source=template`、正文仍是 FL2VA 固定模板；点「开始生成」/单段重跑时不会再生成 Ref2VA 六段提示词。
- 影响：硬切实际用错提示词体系，画面/音频关系与 Ref2VA 预期不符，且界面上看不出。
- 建议：离开 anchor 时把 `prompt_source=template` 的段清空或标为 `prompt_stale` 并让生成前重建；至少不要静默沿用锚定模板。

### P2-3 数字人右栏的段间模式 / 二次采样 / 接缝重叠改动没有进入「脏标记」

- 位置：
  - `web/avatar/js/avatar.js:6199-6203`：只有 `#settings-body` 的 input/change 会 `markFormDirty`；
  - `#f-stitch`（`index.html:268`）、`#f-secondpass`（`:302`）、`#f-seam-overlap`（`:281`）都在右栏，不在 `#settings-body`；
  - `web/avatar/js/avatar-polish.js:291` 只做摘要同步，没有保存/脏标记。
- 影响：改完段间模式或二采开关，页面仍显示「已保存」；切作品时 `confirmDiscardChanges` 不会提示，改动被静默丢弃。
- 建议：给这三个控件（或其容器）加 `markFormDirty`；或者改动即 PATCH 保存。

### P2-4 接缝/混合仍强制要求「潜空间放大器」，与「固定单采」的界面说明矛盾

- 位置：
  - `backend/avatar/workflow.py:1145-1153`：`missing_fields` 用 `ref_second_pass` 判断是否要求 upscaler；
  - `backend/workflow.py:615-622`：MV 侧同样用 `ref_second_pass`，不认 `seam_second_pass`；
  - 调用点：`backend/avatar/job.py:508`（模式 2/3 seam/mixed 也会先走这里）、`backend/avatar/job.py:691`（模式 1 seam）、`backend/jobs.py:615`（MV seam/mixed）。
- 现象：
  - 数字人 seam/mixed 固定 `SamplerCustomAdvanced` 单采，不使用 upscaler，但项目 `ref_second_pass` 默认 true 时仍被判「缺少潜空间放大器」；
  - MV 用户把「接缝二次采样」关掉（`seam_second_pass=false`）后，`missing_fields` 仍按 `ref_second_pass=true` 要求 upscaler。
- 影响：只装了最小模型集（没有 latent upscaler）时，seam/mixed 无法启动，尽管它根本不用放大器。
- 建议：`missing_fields` 按 stitch 判断：seam 看 `seam_second_pass`，mixed 同理；数字人 seam/mixed 直接跳过 upscaler 校验。

### P2-5 数字人包导出/导入丢失 `seam_overlap`（以及非 UI 的生成参数）

- 位置：
  - `backend/avatar/pack.py:666-683`：导出 `generation` 只写 aspect_ratio / output_fps / stitch / anchor_* / ref_second_pass / custom_models，没有 `seam_overlap`；
  - `backend/avatar/pack.py:392-405`：导入也只映射上述字段。
- 影响：模式 2 默认 seam、模式 1/2 mixed 的项目导出再导入后，接缝重叠回到默认 5，窗口计划与导出前不同；用户会以为包完整复刻了项目。
- 建议：导出/导入补 `seam_overlap`（以及 `transition_step/lowres_scale/upscaler_model` 等会影响接缝结果的字段），或在包里明确标注「生成参数不随包携带」。

### P2-6 MV 成片「过期」判断不覆盖 generation 变化

- 位置：
  - `backend/app.py:461-496`：PATCH 项目 generation 时不调用 `_mark_final_stale`；
  - `backend/jobs.py:42-54`：`cuts_signature` 只包含切点与行级 stitch，不含 row.overlap / output_fps / 全局 stitch；
  - `backend/jobs.py:57-74`：seam/mixed 只比较该签名，hard 只比较 take。
- 影响：
  - 改全局 `output_fps`、`seam_overlap`、全局 `stitch` 后，已有成片不会被标为过期；用户可能继续下载旧帧率/旧拼接结果；
  - 行级 overlap 从 22 改 39 也不会触发过期提示。
- 建议：把影响输出的字段纳入 final 指纹，或在 PATCH generation 真正变化时显式 `_mark_final_stale`。

## P3（低风险 / 健壮性 / 文档）

### P3-1 数字人 seam 续跑复用窗口时不校验 latent 文件是否存在

- 位置：`backend/avatar/job.py:1097-1100`、`1121`
- 对比：MV `backend/jobs.py:1093-1100` 会检查 `Path(latent).is_file()`。
- 影响：ComfyUI 的 `output/h3wb/avatarseam/.../seg_*.pt` 被手动清理或迁移后，任务会复用记录并让下游窗口加载不存在的 latent，最终报节点错误；MV 会正确作废。
- 建议：与 MV 对齐，复用前校验 latent 路径存在。

### P3-2 数字人 `/avatar/api/settings` 缺少 MV 侧的 URL 校验

- 位置：`backend/avatar/app.py:525-528`
- 对比：MV `backend/app.py:270-278` 会校验 `comfy_url` / `llm.base_url`。
- 影响：数字人页可以写入非法地址，影响两个工作台共用的 `data/settings.json`。
- 建议：复用 MV 的 `_valid_url` 校验，或在 `settings.save` 前置统一校验。

### P3-3 mixed 在 25/30fps 下，链起点按「逐段四舍五入」累加，可能累计音画偏移

- 位置：`backend/seam.py:190-210`（`target = Σ round(edit_frames × fps / 24)`，`absolute_start += target`）、`backend/jobs.py:1488-1489`（按该起点切链音频）。
- 影响：最终音轨是整条 `source.wav`，而每条链的生成音频从 `plan["start"]` 切片；逐段取整误差最多可累计 ~0.2s（实测 24 段规模），越往后链越可能轻微口型偏移。24fps 下误差为 0。
- 建议：链的绝对起点改用「累计 edit_frames 一次性 round」的精确边界（与 `backend/jobs.py:1695` 硬切做法一致），只在链内做窗口吸附。

### P3-4 文档与实际实现矛盾：作品设定到底是不是弹窗

- 位置：`docs/UI设计说明.md:46` 写「数字人创作设定不再弹窗：左栏常驻「作品设定」dock」；

  代码 `web/avatar/js/avatar.js:6557-6566` 的 `mountSettingsModal()` 也是弹窗实现。
- 影响：后续维护者/Agent 会按错误描述改 UI。
- 建议：把第 46 行改成「作品设定走固定尺寸卡片弹窗，左栏常驻当前作品摘要 + 素材库」。

### P3-5 状态提示与实际能力不一致的小文案

- `backend/avatar/job.py:666` 提示「可勾选“全部重新生成”」，但页面没有该控件（同 P1-2）。
- `web/avatar/js/avatar.js:5337` 模式 2 素材区写「添加参考音色 · 最多 3 个」，但未创建项目时 `handleVoiceFile` 只保存单个 `state.pendingVoice`，再点「添加」会覆盖上一个，不能预先准备 3 个（创建后才能逐个添加）。
