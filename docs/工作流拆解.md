# 原工作流拆解与工作台实现对照

本文记录两份原始 API 工作流的节点链路、关键参数与逻辑，以及工作台如何用纯 Python + 参数化工作流复现它们。

## 1. 参考文件

| 文件 | 作用 |
| --- | --- |
| `MiniMaxH3无限时长数字人工作流 By 像素幻想Lab (self lift双采)API.json` | 长视频编排（H3LVUnified 分段 + 全局运镜 + 提示词扩写 + 逐段提交） |
| `完美Minimax H3 Selflift双采数字人API.json` | 单段最佳实践（9:16 / 2MP、`ref_image_size: max`、SelfLift 参数） |

## 2. 长视频工作流（A）关键链路

```
LoadAudio(232)
   └─→ H3LVUnified(266)  ── 13 个输出 ──┐
        0 audio                          │
        1 ref_audio                      │
        2 length                         │
        3 filename_prefix                │
        4 material                       │
        5–10 ref_images (最多 6 张)        │
        11 string（导演简报/提示词）        │
        12 frame_rate                    │
                                          ▼
H3LVPromptExpand(204)  [视觉模式 qwen3.8-max] → PreviewAny(253) → MiniMaxH3ReferenceToVideo(136)

模型链：
UNETLoader(127)   minimax_h3/minimax_h3_fl2va_int8_convrot
CLIPLoader(128)   qwen3vl_32b_minimax_h3_int8_convrot (type=minimax)
LoraLoaderModelOnly(201)  minimax_h3_fl2v_turbo_4step_v1.2_768p_comfyui_bf16 @ 0.7
ModelAttentionBackend(242) comfy kitchen attention
MiniMaxH3SigmaShift(247)  video 12 / audio 3

采样链：
ResolutionSelector(115) 16:9 / 0.7MP / 32
LTXVConcatAVLatent(246)
BasicScheduler(263) simple 6 steps
H3SigmaRefiner(262) extra_steps 1 / start 0.7 / cosine
SelfLiftAvatarH3Sampler(261) cfg 1 / transition 4 / lowres 0.5 / w 0.5–1 / tiling auto 2
VHS_VideoCombine(195) crf 19 / yuv420p
```

**H3LVUnified 的关键事实**（读 `ComfyUI-H3-LongVideo` 源码确认）：

- 它不是「尾帧续接」。输入只有**一条音频 + 一组固定参考图**，输出是「本段音频 + 帧长 + 提示词 + 同一组参考图」。
- 内部分四步：音频分析 → 动态规划分段 → 全局运镜规划 → 逐段产出简报与提示词。
- 因此段与段之间**不会互相污染**：没有上一段末帧参与条件，画面劣化不会累积。
- 但每段仍然共享「同一个人物参考图 + 同一场景描述 + 统一机位规划」，所以看起来是同一支片子。

工作台默认取 B 的思路（画质优先：`ref_image_size: match` 可切 `max`，crf 可调），参数全部暴露在右栏。

## 4. SelfLiftAvatarH3Sampler 参数

| 参数 | 含义 | 工作台默认 |
| --- | --- | --- |
| `low_res_model` / `high_res_model` | 低清/高清两阶段模型；高清不接则复用低清 | 同一模型链 |
| `vae` | 分辨率跃迁时的像素重编码锚点 | **视频 VAE**（工作流 B 的接法） |
| `latent_image` | 目标分辨率的 H3 AV 潜空间，决定尺寸与时长 | `LTXVConcatAVLatent` |
| `sampler` / `sigmas` | 仅 Euler；SelfLift 复用 transition 预测保持 NFE | `euler` / `simple` 6 步 |
| `transition_step` | 低清阶段的去噪步数 | 4 |
| `lowres_scale` | 低清前缀的空间比例 | 0.5 |
| `rho` | 向像素锚点修正的高风险位置比例 | 0（只用潜空间放大器） |
| `w_min` / `w_max` | 修正强度上下限 | 0.5 / 1.0 |
| `upscaler_model` | 外部 3D 潜空间放大器 | `minimax_h3_latent_upscaler_3d_fp16` |
| `highres_tiling` / `tiling_mode` / `tiling_tiles` / `tiling_axis` | 高清阶段空间分块 | 开 / auto / 2 / auto |

> 注意：工作流 A 把 `vae` 接到了音频 VAE(120)，工作流 B 接视频 VAE(53)。工作台按 B 实现（`vae_video`），因为 SelfLift 的像素锚点需要视频 VAE。

## 5. 分段算法（`segmenter.py`）

移植自 `H3-LongVideo/core.py::segmentation()`，去掉 ComfyUI 运行时依赖。

**候选切点**（每条都带中文理由与置信度，前端会显示）：

| 类型 | 触发条件 | 惩罚 |
| --- | --- | --- |
| `quiet` 持续低人声区 | 局部极小且低能量跨度 ≥ 80ms | 4 |
| `drag_end` 拖音衰减后的能量落点 | 前 200ms 均值比当前高 6dB，后 100ms 接近静音阈值 | 3 |
| `breath` 疑似换气 | 低能量 + 过零率高 | 3.5，附「需要试听」 |
| `valley` 人声局部低谷 | 其他局部极小 | 7，附「可能在句中」 |
| `phrase_gap` 分句间隙 | 相邻 ASR 句中点 ±0.75s 内最低能量点 | 0 |
| `phrase_boundary` ASR 分句边界 | 句间中点 | 5 |
| `section` 无人声段边界 | intro / interlude / outro 起止 | 2 |
| `word_fallback` 词界回退 | 词尾时间戳 | 12 |
| `forced` 时长强制回退 | 每 `target` 秒兜底 | 40 |
| 端点 | 0 与全曲末尾 | 0 |

**动态规划**：对每个终点枚举起点（跨度 ≤ `maximum`，≥ 3s），

```
score = cost[start] + 0.5
      + ((span - target) / 4)^2
      + candidate.penalty
      + 2 * relative_level           # 相对能量 [0,1]
      + beat_offset * 0.35           # 距最近节拍的偏移（上限 0.5）
```

另外：与估计词时间戳重叠 +20；跨度过短额外 +5。最后回溯出边界，覆盖 0 → 全曲。

**帧数**：`frames_for = 5 + 17*ceil((max(124, ceil(seconds*24), edit_frames) - 5)/17)`，
`edit_frames` 是实际剪辑长度（`frames_for(duration)`），`generation_frames` 是实际提交给 H3 的帧数（为下一段留出对齐余量）。

## 6. 导演规划（`director.py`）

移植自 `H3-LongVideo/director_rules.py` + `defaults/director_config.json`。

- **能量分带**：全片能量 33/66 分位 → low / medium / high。
- **运镜池**（演唱模式）：
  - low：`micro_reframe` / `arc_left` / `arc_right` / `dolly_out`
  - medium：`arc_left` / `arc_right` / `truck_left` / `truck_right` / `micro_reframe` / `dolly_in` / `dolly_out`
  - high：`dolly_in` / `dolly_out` / `arc` / `truck` 等
  - 口播模式固定中近景正面，运镜保守。
- **约束**：
  - 相邻段不得重复同一运镜家族（`dolly_in`/`dolly_out`、`truck_left`/`truck_right`、`arc_left`/`arc_right` 各算一族）；
  - 横向运镜左右交替；
  - 禁止越轴：人物正面前方 ±30° 内不跨越；
  - 用 `sha256(signature + 段号 + 类别)` 抽签，保证同参数结果可复现。
- **每段产出**：`camera_start` / `camera_end` / `camera_move` / `entry_cut_strategy` / `entry_cut_risk` / `brief`（中文六字段导演简报）。

## 7. 提示词（`prompts.py`）

**中文导演简报**六字段：

```
画面任务 / 声音关系 / 开场构图 / 主体动作 / 镜头运动 / 结束构图
```

**英文 H3 Ref2VA 提示词**六段（每段以 `<Subject 1> <Audio 1>` 结尾）：

```
1) 镜头与剪辑  2) 可见动作  3) 环境  4) 人物与音频同步  5) 同期声  6) 结束构图
```

硬规则（校验器会拦）：

- 参考图正文里第一次引用后紧跟 `<Picture N>`，且编号从 1 连续；
- 禁止跨段指代（`same as previous`、`the woman again` 等）；
- 禁止把音频写成画面事件（不能出现「听得到」「声音响起」这类描述画面外声源的句子）；
- 图像内禁止文字 / 水印 / 字幕；
- 每段必须有 `<Subject 1>` 与 `<Audio 1>` 锚点。

LLM 扩写失败（格式不合格 / 超时 / 未配置）时，自动回退到确定性合成器，保证永远能出可用的提示词。

## 8. 工作台实现与原始节点对照

| 原节点/模块 | 原职责 | 工作台实现 |
| --- | --- | --- |
| `H3LVUnified` | 音频分析 + 分段 + 运镜 + 简报 + 输出素材 | `audio.py` + `segmenter.py` + `director.py` + `prompts.py` |
| `H3LVPromptExpand` | 调 qwen3.8-max 扩写 | `llm.py`（OpenAI 兼容 / Ollama，可换成任意服务） |
| `PreviewAny` | 展示提示词 | 前端提示词弹窗（可编辑 + 校验） |
| `MiniMaxH3ReferenceToVideo` | 参考图条件 + 音频条件 | `workflow.py` 同节点同参数 |
| `SelfLiftAvatarH3Sampler` | 双采 | `workflow.py` 同节点同参数 |
| `VHS_VideoCombine` | 出片 | `workflow.py` + `media.py` 二次归一化 |
| `controller.py` 拼接 | ffmpeg 拼接 | `media.concat()`（原曲音轨 + faststart） |
| 节点 UI 的分段表 | 查看/调整 | 前端分镜卡 + 波形时间线 |

## 9. 为什么不用 `H3LVUnified` 节点本身

1. 该节点把 LLM 固定为内部 `qwen3.8-max`，无法接云端或 Ollama；
2. 它的输出契约与本工作台的数据模型不完全一致（前端需要可编辑的分镜、提示词、参考图角色）；
3. 直接复用节点会让工作台强依赖 ComfyUI 的图结构与版本，移植性差；
4. 分段 / 运镜 / 提示词逻辑本身是纯 Python，抽出来后可以脱离 ComfyUI 单测与调参。

因此工作台**复刻逻辑而不复用节点**，只在最后一步把参数化的单段图提交给 ComfyUI。
