# 数字人工作台 · 技能接入报告（接入点与缺口）

> 状态：设计报告（未改代码）。依据两份材料：
> - 用户选定的方案 1：把「音频驱动（模式 1）」迁进数字人页面，尽量解耦；
> - 技能 `h3-talking-head-motion-graphics-director`（H3 口播动态图形导演）：
>
> 目标：在现有数字人工作台（模式 2/3 已上线、A/B/C 三腔提示词已接入）基础上，补上
> 「模式 1 音频驱动」并让整套设计走技能的分镜/节拍/动效/音色/校验体系。

---

## 1. 技能带来的增量（相对当前实现）

当前实现已经具备：三腔互斥（A/B/C）、5 书面字/秒预算、Ref2VA 六段式、按模式注入
系统提示词、模式 2 `ref_audios` / 模式 3 原生音轨、逐段生成 + 拼接。

技能补充的是**设计层与校验层**：

| 技能要求 | 当前状态 | 差距 |
| --- | --- | --- |
| 音频方式三选一（音频驱动 / 参考音色 / 无音频参考） | 已按模式固定 A/B/C | 模式 1 还没有落地 |
| 语速预算 ~5 书面字/秒、报告字数与目标语速 | 已按 5 字/秒分段 | 提示词里没有强制写"目标语速 + 字数"；lint 未接 |
| 语义节拍图（触发词/沟通职能/主辅效果/锚点层级/生命周期/语义终点/说话人/注意目标/情绪反应/口呼吸/手势准备/恢复） | 无 | 需要结构化存储 + 编辑器 |
| 效果系统六个"一"（字体/材质/图标族/运动语法/主辅色/入场方向与深度） | 无 | 需要 `design.style_system` |
| 四轴分类（信息格式 × 运动行为 × 空间行为 × 视觉风格）与密度（低/中/高） | 无 | 需要设计字段 + 预设库 |
| 动效生命周期配对（入场→落定→可读停留→退场→干净恢复） | 只在提示词文本里靠模型自觉 | 需要节拍表 + lint 校验 |
| 人物表演因果链（注意目标→意图→可见反应→恢复）、眨眼/呼吸/口型/手势规范 | 系统提示词里已覆盖 | 缺工作台级可编辑字段与校验 |
| C 腔 10 维 voice card | 只有一段自由文本 `voice_description` | 需要结构化字段 + 生成/重写 |
| 构图/安全区/可读性/闪烁安全/复杂度预算 | 无 | 需要字段 + lint |
| 提示词结构 lint（字段顺序/混 schema/音频模式/Audio 标签/台词块/特效配对/人物真实感/长度 ≤7000） | 只有 `<d>` 与音频标签的轻量检查 | 需要移植技能 lint 并接入生成流程 |
| 输出三段式（摘要行 + 提示词 + 可选生成前检查） | 只存提示词正文 | 需要解析/保存摘要与 lint 结果 |

## 2. 方案 1：模式 1（音频驱动）迁入数字人页面（解耦设计）

### 2.1 原则

- **不修改 MV 的任何现有代码/页面/接口**；只读取复用 MV 的纯函数模块：
  - `backend/audio.py`（解码/波形/切片）
  - `backend/segmenter.py`（音频分段 + `frames_for`）
  - `backend/workflow.py::build`（锁定音轨 + SelfLift 双采的 MV 工作图）
  - `backend/media.py`（归一化/拼接/封面）
- 数字人侧新增独立模块承载模式 1，数据仍写 `data/avatar/projects/<id>/`。
- 模式 2/3 的现有链路不动；模式 1 只在「工作流选择」和「成片音轨」上分叉。

### 2.2 需要新增/修改的接入点

| 位置 | 改动 |
| --- | --- |
| `backend/avatar/config.py` | 增加模式 1 常量与默认参数（音频驱动是否启用、固定机位；默认 `max_seconds=15`） |
| `backend/avatar/store.py` | 项目新增 `audio` / `analysis` / `asr` 字段；`create()` 支持 mode=1 且 audio 可为空（先建项目后上传） |
| **新模块** `backend/avatar/audio_pipeline.py` | 音频上传后解码→分段→产出 segments（调用 MV `segmenter.segment`）；可选 ASR（MV `asr`）；`slice_frames` 切本段音频；帧数用 `segmenter.frames_for` |
| **新模块** `backend/avatar/job.py`（扩展） | `_run` 按 mode 走两个分支：模式 2/3 用 `avatar/workflow.py`；模式 1 用 MV `workflow.build`（传入本段 audio.wav 文件名），成片用 `media.concat(..., source.wav, ...)` 混原音 |
| `backend/avatar/plan.py` | 模式 1 用 A 腔提示词（已内置），任务书补充"驱动音频为最终时间轴"；分段来源改为音频分析 |
| `backend/avatar/app.py` | 新增音频相关接口（见 §4）；`POST /projects` 允许 mode=1 |
| `web/avatar/*` | 模式 1 卡片改成完整表单：音频拖入、波形时间线（先只读）、自动分段、段卡、生成 |
| 测试 | 新增 `avatar_audio_smoke_test.py`：合成音频→上传→分段→伪造 take→合成时验证**成片音轨 = 原音频**（可复用 MV smoke 的合成音频方法） |

### 2.3 模式 1 数据/算法约定

- 解码统一 `data/avatar/projects/<id>/source.wav`（44.1kHz 双声道），与 MV 一致。
- 分段：`segmenter.segment(samples, sr, transcript, "speaking", maximum, target, script)`，
  目标/最长段长复用项目字段（默认 8 / 12 秒，可调 5–15）。
- 每段 `frames = segmenter.frames_for(edit_frames, 24)`（MV 同款 5+17k 对齐），
  生成时用 MV `audio.slice_frames` 切段并补静音到 generation_frames。
- 成片：逐段 `media.normalize` → `media.concat(norms, source.wav, final, total_frames, work)`，
  即**成片音轨 = 原始驱动音频**（这是模式 1 与模式 2/3 的核心差异，必须在 job 分叉里落实）。
- 提示词：A 腔（`backend/avatar/system_prompts/A-音频驱动.md`）已内置，规则是"不出现任何
  `<Audio N>` 与音频任务/保留行"，并要求写"平台运行时驱动音频提供最终口播时间线"。

## 4. 接口变化

### 4.1 新增

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/avatar/api/projects/{id}/audio` | 上传/替换驱动音频（mode=1，解码成 source.wav） |
| DELETE | `/avatar/api/projects/{id}/audio` | 删除驱动音频 |
| POST | `/avatar/api/projects/{id}/analyze` | 音频分析 → 自动分段（可选 ASR，参数 use_asr/model/language） |
| PUT | `/avatar/api/projects/{id}/cuts` | 手动切点（Phase 2；帧/秒数组） |
| GET/PATCH | `/avatar/api/projects/{id}/design` | 读取/更新设计层（密度/风格系统/安全区/voice card/品牌） |
| POST | `/avatar/api/projects/{id}/design/suggest` | （可选）让 LLM 按文案+素材给出节拍表/效果系统建议 |
| POST/PATCH/DELETE | `/avatar/api/projects/{id}/segments/{i}/beats[/{j}]` | 节拍表增删改 |
| POST | `/avatar/api/projects/{id}/segments/{i}/prompt/lint` | 只跑提示词 lint，返回结构化结果 |
| POST | `/avatar/api/projects/{id}/segments/{i}/prompt/repair` | 按 lint 问题让 LLM 修复一轮（复用三腔系统提示词） |
| GET | `/avatar/api/effect-catalog` | 技能效果库精编：语义→主效/辅效/避坑、四轴分类、密度预设、风格系统预设 |

### 4.2 修改（保持向后兼容）

- `POST /avatar/api/projects`：`mode` 允许 1；`audio` 可选（mode=1 可后传）。
- `POST /avatar/api/projects/{id}/plan`：mode=1 走音频分析（读 audio），mode=2/3 走台词规划。
- `POST /avatar/api/projects/{id}/segments/{i}/prompt`：user 任务书增加 `design` 与 `beats` 结构化 JSON；
  返回增加 `prompt_meta`（摘要行、lint 结果）。**返回字段只增不减。**
- `GET /avatar/api/projects/{id}`：项目 JSON 新增 `audio/analysis/asr/design`，
  segments 新增 `beats/prompt_meta`（旧前端忽略即可）。
- `POST .../generate`：mode=1 走音频驱动分支（工作流 = MV `workflow.build`，成片混原音）；
  mode=2/3 不变。

## 5. 渲染能力变化（用户可见）

| 能力 | 现在 | 接入后 |
| --- | --- | --- |
| 音频方式 | 模式 2 参考音色 / 模式 3 无音频（模式 1 跳 MV） | A/B/C 三腔都在数字人页；模式 1 直接上传音频对口型，成片保留原音 |
| 画面 | 固定机位口播（提示词控制） | 不变（单镜头固定机位），但允许技能规定的极小缓推/构图约束；段落之间仍是硬拼接 |
| 动态图形 | A/B/C 系统提示词已会写"信息卡/文字/图标"，但无结构化设计与校验 | 每个语义节拍有：触发词、主/辅效果、锚点层级、可见文案、入场→落定→停留→退场→恢复；同时只允许 1 组 |
| 文字/数字 | 由 H3 生成，可能崩字 | 技能强制"引号写死 + 字形/字序/断行稳定条款 + 整词/整行显现 + ≤7000 字符"，lint 会点名缺稳定性条款 |
| 时间控制 | 模式 2/3：5 字/秒估算；模式 1：无 | 模式 1：以驱动音频实际波形为时间轴（有 ASR 时可到词级触发点）；模式 2/3：5 字/秒预算 + 时长对齐 |
| 音轨 | 模式 2/3 用 H3 生成音轨拼接 | 模式 1 用原始驱动音频；模式 2/3 不变 |
| 效果安全 | 提示词里零散约束 | 安全区/遮挡保护/闪烁 ≤3 次/秒/复杂度预算变成设计字段 + lint 检查 |
| 可交付性 | 提示词一坨文本 | 摘要行 + 六段提示词 + lint 结果 + 可修复；设计层可复用（同一套风格系统跨段一致） |

**重要边界**：这里的"渲染"是 H3 在生成视频时**把动态图形画进画面**，不是后期的确定性合成。
因此字形/logo/图标准确性仍是概率性的；如果后续需要像素级文字/品牌 logo，需要另走
HyperFrames 后处理叠加（可作为 Phase 3 的确定性兜底，不与 H3 管线冲突）。

## 7. 缺口与风险（按优先级）

### P0（必须解决，否则功能不完整）

1. **模式 1 管线缺位**：音频分析/分段/切片/成片混原音在数字人侧都不存在；需要新模块，
   但可全部通过只读复用 MV 纯函数实现（不动 MV）。
2. **提示词 lint 未接**：技能的结构检查（字段顺序、混 schema、Audio 规则、特效配对、
   人物真实感、长度）是质量底线；必须先落成 `lint.py` + 接口。
3. **提示词任务书不含设计/节拍**：现在只给"文案+时长+画幅+参考图"，模型自由发挥；
   必须把 `design`/`beats` 结构化喂进去，否则技能规则无法落地。
4. **摘要行/prompt_meta 未存**：技能要求报告语速/字数/路线/密度；需要解析保存，供 UI 展示。

### P1（体验与质量）

5. **设计面板与节拍编辑器的复杂度**：完整六"一"+四轴+节拍表 UI 工作量大；建议先做
   "密度 + 主辅色 + 字体语言 + 卡片材质 + 效果清单 + 每段节拍表（可选自动建议）"，
   高级字段折叠。
6. **C 腔 voice card 结构化**：10 维字段需要生成/重写入口（可由 LLM 从人设/场景生成初稿）。
7. **模式 1 手动切点/波形编辑**：可先自动分段，波形只读；手动切点后置。
8. **效果一致性跨段**：同一套风格系统 + 每段独立生成 + 硬拼接，段落间图形风格需靠
   design 统一；拼接处无法做图形跨段连续动画（提示词必须片内收尾）。

### P2（能力边界/风险）

9. **H3 文字保真**：动态图形里的中文/数字/logo 仍是生成式，可能崩字；技能用
   "引号写死+整词显现+稳定性条款"缓解，但不能承诺。需要真实 GPU 抽样验证。
10. **7000 字符提示词预算**：图形细节写满容易超；需 lint 告警 + 自动简化策略（保留人物
    → 主信息 → 手部/产品 → 构图安全 → 次级图标 → 粒子）。
11. **多说话人**：技能支持，但当前管线单 performer（`performer` 只取一张）；多说话人
    需要按音轨/角色拆分项目，暂不支持。
12. **ASR 依赖**：模式 1 想做到词级触发点需要 ASR（可选依赖），无 ASR 时只能按分段
    与估算时间给触发词。
13. **成本/耗时**：提示词从"模板直出"变成"LLM 生成 + lint + 可能修复一轮"，
    每段可能 +30–120 秒（本地 9B 实测 30–40 秒/段，重试翻倍）；生成总时长感知明显。
14. **真实渲染验证**：动效图形是否按提示词生成、文字是否可读，必须每类效果抽 1–2 段
    真跑验收；这会占 GPU。

| **P1**（模式 1 落地） | 音频上传/分析/分段/切片 + A 腔提示词 + 锁定音轨生成 + 原音合成 + 模式 1 UI（自动分段） | 中（新管线，复用 MV 纯函数） | P0 的字段 |

| **P3**（可选增强） | 波形手动切点、效果预设库、跨段设计一致性检查、HyperFrames 确定性文字/logo 叠加兜底 | 高（跨系统） | P2 |

验收方式：
- P0：lint 单测（好/坏提示词各一组）+ 三腔生成任务书快照 + 冒烟测试；
- P1：合成音频 → 上传 → 分段 → 伪造 take → 合成成片并断言音轨是原音频；真实 GPU 跑 1 段；
- P2：带 design/beats 生成提示词，lint 0 error；UI 操作路径冒烟；
- P3：抽样真跑 2–3 个效果（信息卡/图标/下三分之一），检查可读性与安全区。
