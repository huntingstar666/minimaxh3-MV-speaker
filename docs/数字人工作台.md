# 数字人工作台（模式 1 / 2 / 3）

数字人模式从 MV 工作台顶部「数字人工作台」进入，是一个**独立子应用**：

- 页面：`/avatar/`（`web/avatar/`，零构建原生前端）
- 接口：`/avatar/api/...`（`backend/avatar/`）
- 数据：`data/avatar/projects/<id>/`（与 `data/projects/` 的 MV 项目完全隔离）
- MV 侧唯一的改动：`backend/app.py` 一行 `app.mount("/avatar", avatar_app)`，
  `web/index.html` 顶部一个入口按钮；MV 的页面逻辑、任务、数据格式零改动。

## 三种模式

| 模式 | 输入 | 用哪套工作流 | 成片音轨 |
| --- | --- | --- | --- |
| 1 · 音频驱动（A 腔） | 驱动音频 + 参考图（+ 可选台词） | MV 的锁定音轨工作流：`LoadAudio → LTXVAudioVAEEncode → SolidMask(0) → SetLatentNoiseMask → LTXVConcatAVLatent` + SelfLift 双采；可选**首尾帧锚定**（锚定下 `plain` 单采 / `selflift` 双采） | **原始驱动音频** |
| 2 · 参考音色（B 腔） | 完整录音或短音频（自动截取 12s 音色样本，可试听/改起点）+ 台词 + 参考图 | 数字人工作流：Ref2VA `ref_audios` + SelfLift 双采 + `VAEDecodeAudio` | H3 生成音轨（按段拼接） |
| 3 · 无音频参考（C 腔） | 台词 + 音色卡 + 参考图 | 同上，但不传参考音频（原生生成语音） | H3 生成音轨（按段拼接） |

## 画幅与输出尺寸（必须先对齐参考图）

输出比例由 `generation.aspect_ratio` 决定，实际像素由 `ResolutionSelector(aspect_ratio, megapixels, multiple)` 计算。
**这条链路不会自动读取参考图比例**：比例填错不会报错，只会让锚定图在 `anchor_preprocess=center_crop` 时被裁掉一大块，成片人物/背景跟着变。

| `aspect_ratio` | `megapixels` | `multiple` | 实际输出 |
| --- | --- | --- | --- |
| `16:9 (Widescreen)` | 1.0 | 32 | **1376×768** |
| `9:16 (Portrait Widescreen)` | 1.0 | 32 | **768×1376** |

规则：

1. **以参考图实际像素比例为准**（本仓库常驻参考图 1936×1088 = 16:9 → 用 16:9，输出 1376×768）；
2. 用户点名尺寸时，开工前把「比例 + 实际像素 + 裁剪影响」写清楚再提交生成；
3. 9:16 对 16:9 参考图意味着居中裁掉左右约 2/3 宽度，只在明确要竖屏时使用；
4. 尺寸是结构参数：错了整批 take 作废，必须先确认，再跑全量。

> 切换模式（`PATCH /avatar/api/projects/{id}` 且 `mode` 变化）会清空分段/分析结果，并移除
> 新模式不需要的音频素材（mode1→其他删 `source.wav`、非 mode2 删 `voice/ref.wav`）。
> 这样避免 mode1 按音频切出来的任意帧数被 mode2/3 当成 H3 长度提交。

三腔系统提示词随仓库携带：`backend/avatar/system_prompts/{A-音频驱动,B-参考音色,C-无音频参考}.md`，
按项目 `mode` 自动注入；可用 `GET/PATCH /avatar/api/prompts` 覆盖（传空字符串恢复内置）。

## 首尾帧锚定（模式 1 可选）

模式 1 可以额外选择「首尾帧锚定」：每段用 `MiniMaxH3ImageToVideo`，首帧和尾帧都接本段第一张参考图；全项目共用固定种子；段与段之间不传任何画面/latent，因此不会把上一段的劣化带到下一段。

- `generation.stitch = "anchor"`（仅模式 1；模式 2/3 会自动回 `hard`）；
- `anchor_seed`：0 = 由项目 id 派生固定种子；所有段共用；
- `anchor_mid`：`none / center / thirds / custom`，默认 `center`（段中点再锚一次同图，压住背景漂移/第二人）；
- `anchor_preprocess`：`center_crop / stretch / none`，默认 `center_crop`（`MiniMaxH3ImageToVideo` 对 first 拉伸、last 裁切，必须先裁成目标画幅）；
- `anchor_upscale`：`ImageScale` 插值，默认 `lanczos`；
- `anchor_sampler`：`plain`（默认，单采，`SamplerCustom` 一次出图，最平滑）/ `selflift`（双采：Fix 二采 + 分块）；二采走 `SelfLiftAvatarH3SamplerFix`（`highres_tiling=true`）+ `LTXVSeparateAVLatent → VAEDecode`，并自动关闭中间锚点；旧版节点自动回退 `SelfLiftAvatarH3Sampler`（`highres_tiling=false`）；
- 提示词走 FL2VA Base 模式（`Picture 1/Picture 2` 对齐 0.00s/末帧 + `integrated_multimodal_description`），不写台词文本，避免屏幕出字；
- **默认提示词模板**：`plan.ANCHOR_DEFAULT_PROMPT`（固定文案，只替换末帧时间点）。音频分析 / 拖切点 /
  拆分合并 / 改项目参数时，后端会把模板写进每段 `segments[].prompt`（`prompt_source=template`）；
  用户手改后变 `manual`，生成时优先用用户版本（`job._generate_segment_mode1`）；
  「AI 生成 / 生成全部提示词 / lint / 修复」在锚定下也只写固定模板、跳过 Ref2VA lint，不调用 LLM；
- **文案禁忌**：不要在锚定提示词里写 `black` 之类的"不要出现某颜色"否定句——单采（`SamplerCustom`）
  会把背景压成纯黑；默认模板已规避这一点；
- 布局：**左栏是内容与创意**（创作模式 → 作品内容：名称/台词/创作要求/语速/段长/驱动音频 → 参考图 → 设计 → 最近作品）；**右栏是运行参数与结果**，顶部两个 tab：「参数」= 首尾帧锚定 + 生成参数（画幅/清晰度/种子/高级模型）+ 系统提示词，「运行 / 成片」= 运行状态 + 成片；生成中自动切到结果 tab；窄屏顺序为 内容 → 工作区 → 参数；
- **系统提示词面板只覆盖 Ref2VA（模式 1/2/3 的 LLM 系统提示词），首尾帧锚定不走它**：锚定提示词来自 `plan.ANCHOR_DEFAULT_PROMPT` 或用户手改版本，不经过 LLM，可在每段「提示词」里查看和修改；
- 仍逐段生成，单段重生成/换片可用；成片按 `edit_frames` 拼接，音轨用原始 `source.wav`。

> 二采 Fix + 分块 + 无中间锚：1MP / steps6 / lowres0.5 时 max 3.26；steps10 → 1.28；steps10 + lowres0.75 + manual 2 块 → 0.96（mean 0.369）。`tiling_mode=auto` 在 0.4MP/1MP 实际选 1 块（等于没分块）。`plain` 仍最平滑（max 0.62）且是默认。首尾钉帧可让拼接处与参考图完全一致，但会把段内首尾 1 帧变成硬切（max 3.26 → 5.69），默认关。2MP 全量仍需单独验收。

## 模式 1：音频驱动（不再跳 MV）

1. 新建作品（mode=1）→ 上传驱动音频（mp3/wav/m4a/flac/mp4…，解码成 `source.wav`）；
2. 「分析音频并分段」：MV `segmenter` 声学分析 + 可选 ASR（faster-whisper）→ 分段；
   目标/最长段长 5–30s（默认 8/12，推荐 ≤15s，30s 为压力上限）；没有 ASR 时按台词比例分配文本；
3. 波形时间线：切点竖线可拖 → `PUT /cuts`（内部切点、绝对秒、升序）；播放头切分 →
   `POST /segments/{i}/split`（绝对秒）；段卡合并 → `POST /segments/{i}/merge`；
   切点没变化时 no-op（不丢 take）；
4. 提示词走 A 腔（提示词里没有任何 `<Audio N>`；写明"平台运行时驱动音频"同步）；
5. 生成：`stitch=hard` 时逐段调用 MV 锁定音轨工作流；`stitch=anchor` 时逐段走首尾帧锚定
   （提示词默认用固定模板，手改后用用户版本；`anchor_sampler` 选 `plain` 单采或 `selflift` 双采）；
   两种方式都先切本段音频并补静音到 H3 合法帧数；
6. 合成：每段按 `edit_frames` 归一化后拼接，**直接使用原始 `source.wav` 作为成片音轨**
   （`final.audio_source = "original"`）。

## 模式 2 / 3：参考音色与无音频

- **模式 2（参考音色）**：音频槽是「音色样本」而不是驱动音频。可上传完整录音（≤10 分钟）：
  后端保留 `voice/source.wav`，自动截 **12 秒**（2–15 秒可调）到 `voice/ref.wav` 作为 H3 的
  `ref_audios`；页面可拖起点、点「试听」确认，`POST /avatar/api/projects/{id}/voice/sample`
  重新截取（`start_seconds` / `length_seconds`）。视频时长由台词分段决定，不由参考音频决定。
- **模式 3（无音频参考）**：不需要任何音频；贴整段台词 → 点「按台词分段」即可自动按标点/语速分段，
  不需要手动一句句拆。
- 切换模式会清掉不属于当前模式的待上传素材（mode2 的参考音频、mode1 的驱动音频），避免误提交。

## 设计层（技能《H3 口播动态图形导演》）

设计面板是**带预览的卡片式**：顶部有 9:16 迷你预览（人物 + 安全区 + 主色 + 效果卡片，
随密度/主辅色/图形模式/效果族实时变化）；「效果密度」是三张缩略图卡片；
「风格系统」是 8 张风格缩略图卡片，点选后自动带出字体/材质/图标/运动语法/主辅色；
「效果清单」每个效果族也带缩略图。缩略图全部由前端代码绘制 SVG（零外部依赖），
不依赖生图服务，离线可用。

项目 `design` 字段（`GET/PATCH /avatar/api/projects/{id}/design`）：

- 基础：`effect_density`（低/中/高）、`effect_families`（效果族多选，来自 `/effect-catalog`）、
  `style_system`（字体语言/卡片材质/图标族/运动语法/主辅色/视觉风格）；
- 安全：`platform` + `safe_area`（上/下/左/右 0–0.35）、`graphics_budget`
  （同时 1 组、闪烁 ≤3 次/秒、提示词 ≤7000 字符）；
- C 腔：`voice_card` 10 维（呈现/年龄带/音高/共鸣/质感/咬字/语速分句/语调/情绪立场/收音/anti-style）；
- 品牌：`brand.palette / typography_note / logo_refs`；
- 图形模式：`generated`（H3 画进画面）/ `overlay`（提示词不画图形，后期确定性叠加）。

「AI 建议」：`POST /design/suggest {mode: effects|voice|beats, segment_index?}`（小提示词 LLM，
不加载 1.3 万字导演文档）。

## 节拍表（beats）

每段可编辑语义节拍：触发词、沟通职能（hook/definition/number/list/steps/…）、主/辅效果、
锚点与层级、可见文案、生命周期（入场→落定→停留→退场→干净恢复）、注意目标、手势、风险。
- `POST/PATCH/DELETE /segments/{i}/beats[/{j}]`；
- 生成提示词时把节拍表作为 JSON 注入任务书；没有节拍表时让模型自己设计并在 `BEATS:` 行返回，
  后端解析后回填（不写进提示词正文）；
- 点「AI 建议节拍」可让 LLM 生成初稿。

## 提示词生成流程

> 首尾帧锚定**不走下面这套 LLM 流程**：直接用 `plan.ANCHOR_DEFAULT_PROMPT`（或用户手改版本），
> 由 `job._generate_segment_mode1` 读取。下面只针对 Ref2VA（`stitch=hard` / 模式 2 / 模式 3）。

1. system = 三腔系统提示词（A/B/C 文件，按 mode 注入）；
2. user = 中文任务书：音频腔/文案/时长/帧数/画幅/参考图清单/参考音频/音色卡/设计层 JSON/节拍表 JSON/输出格式；
3. LLM 调用（`backend/avatar/llm_client.py`）：
   - `max_tokens ≥ 16384`、`timeout ≥ 900s`；
   - Ollama（11434）额外带 `options.num_ctx=32768`，避免长系统提示词被默认上下文截断；
4. 输出解析：`SUMMARY:` 行（兼容裸 `路线=Ref2VA …` 首行）+ `BEATS:` JSON + 六段正文；
5. `backend/avatar/lint.py` 结构校验（六段顺序/混 schema/[Shot 1]/A 腔禁止音频标签/
   B 腔 `<Audio 1>`+`audio reference`+`reference` 保留行/C 腔 10 维音色卡/台词块与语速预算/
   引号文案稳定性/特效配对与安全区/人物真实感/闪烁/≤7000 字符；overlay 模式跳过特效检查）；
6. 不合格自动修复一轮（把 lint 问题回喂），仍不合格回退内置六段模板；
7. 结果保存：`prompt` + `prompt_source` + `prompt_meta`（摘要行、字数/语速、效果数、lint、task_types）。

## P3 兜底：确定性文字/logo 叠加（overlay 模式）

`design.graphics_mode = "overlay"` 时：提示词不生成任何文字/图形，由 `backend/avatar/overlay.py`
用 **ffmpeg drawtext + overlay** 在生成后叠加：

- 时间：`beat.trigger` 在台词中的字符位置 ÷ 5 字/秒 → 起点，持续到下一 beat 或 +2.5s；
- 位置：`anchor` 映射安全区（right_side / lower_third / top_left / beside_speaker / world_space / surface）；
- 样式：accent 主色 + secondary 辅色、material 决定底框/描边、字号按画面高度自适应；
- logo：`brand.logo_refs` 第一张可读图叠右上角（宽 ≤18%，α 0.9）；
- 中文用 `textfile=` + `expansion=none` + `msyh.ttc`；失败保留原视频并记 warning；
- 生成时自动应用；也可对已生成片段重跑：`POST /projects/{id}/overlay`。

## 包导入 / 导出（.h3avatar.zip）

对齐技能 `skills/mv-pack-builder/references/avatar-package-format.md`（schema `h3-avatar-pack`，version 1）：

- **导入**：`POST /avatar/api/projects/import`，multipart `package`（`.h3avatar.zip`/`.zip`）+ 可选 `name`。
  页面「最近作品」面板也提供「导入 .h3avatar 包 / 导出当前包」按钮。
  manifest 允许 `manifest.json` / `h3avatar.json` / `avatar.json`，也允许整包套一层目录
  （与技能校验器一致）；没有提示词的草稿包可以导入，会带一条 warning。
  一次性落库（不走 create→PATCH）：mode/workflow/design/segments/beats/prompt 直接写入；
  mode1 安装 `audio/source.wav` 并把包内 H3 帧数按比例映射到真实音频边界；mode2 安装
  `voice/reference.wav`；参考图复制进 `refs/`；`prompt_meta` 以服务端 lint 重算（保留包内
  summary/task_types，`source="import"`）。包结构错误返回 400。
- **导出**：`GET /avatar/api/projects/{id}/export` → `.h3avatar.zip`（manifest.json + design.md +
  audio/voice/refs + 每段提示词）。导出包可被技能自带校验器
  `validate_avatar_pack.py --require-prompts` 直接校验通过。
- 测试：`python avatar_pack_smoke_test.py`（mode1/mode2/mode3-overlay 导入、导出、roundtrip、
  非法包拒绝、技能校验器交叉验证）。

## 数据与接口速查

> 导演化字段：`material_note`（全局创作要求）、`segment.note`（本段创作要求）、
> `segment.ref_ids`（本段启用的参考图，null=全部）、`voices`（模式 2 的音色素材列表，可为多个；
> 音色只是素材，不与人物绑定，谁用什么由提示词/创作要求决定）、`speakers`（可选的人物提示表）。
> UI：左栏「全局创作要求」+ 段卡「本段创作要求」（支持 `@图N`、模式 2 支持 `@音频N`，@ 弹窗可预览图片/试听音色）；
> 段卡「提示词」入口常驻（手写/粘贴/AI 生成，生成中显示耗时）；段卡「本段参考图」可勾选本段用图并显示
> `<Picture n>=图N` 对照，缩略图点开即可预览；模式 2 段卡还有「本段音色」行，可直接试听每个音色
> （被创作要求引用的会标「本段引用」）；模式 1 段卡「试听」按段播放；片段缩略图点击弹窗预览；模式 2 左栏是音色库
> （多个音色可添加/试听/改名/删除）；切换创作模式会真正保存到当前作品，并按台词自动重建分段。
> 多音色接口：`POST/PATCH/DELETE /avatar/api/projects/{id}/voices[/{voice_id}]`。
> `.h3avatar` 包会携带 `material_note` / `speakers` / `segments[].note` / `segments[].ref_ids`
> 存储/显存维护：见 `docs/资源与显存管理.md`（维护 API、清理 CLI、显存释放、上传上限）。
> 与 `voices[]`；导出不再强制 `voice/ref.wav`（多音色项目按 `voices[]` 导出，

项目新增字段：`audio` / `analysis` / `asr`（模式 1）、`design`、`segments[].beats`、

## 已知限制

- 单说话人：当前只支持 1 位 performer（多说话人需按人拆项目）；
- H3 生成式文字仍可能崩字：需要精确文字/logo 时用 overlay 模式；
- overlay 只做单段叠加（成片拼接后不再统一重叠加），换行按字符数估算；
