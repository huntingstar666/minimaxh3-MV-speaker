# 数字人工作台（模式 2 / 模式 3）

数字人模式从 MV 工作台顶部「数字人工作台」进入，是一个**独立子应用**：

- 页面：`/avatar/`（`web/avatar/`，零构建原生前端）
- 接口：`/avatar/api/...`（`backend/avatar/app.py`）
- 数据：`data/avatar/projects/<id>/`（与 `data/projects/` 的 MV 项目完全隔离）
- MV 侧唯一的改动：`backend/app.py` 一行 `app.mount("/avatar", avatar_app)`，以及
  `web/index.html` 顶部多一个入口按钮；MV 的页面逻辑、后端任务、数据格式零改动。

## 三种模式

| 模式 | 入口 | 输入 | 用哪套工作流 |
| --- | --- | --- | --- |
| 1 音频驱动 | 数字人页面里的卡片 → 跳回 MV 工作台 | 现成音频 + 参考图 | MV 的 `backend/workflow.py`（锁定音轨 + SelfLift 双采，对口型） |
| 2 参考音色 | 数字人页面 | 2–15s 参考音频（音色）+ 台词 + 参考图 | 新工作流：Ref2VA 的 `ref_audios` + 原生生成音轨 |
| 3 无音频口播 | 数字人页面 | 台词 + 音色描述 + 参考图 | 同上，但不传 `ref_audios`（T2VA 式原生口播） |

模式 1 复用 MV 工作台而不复制一份实现：MV 已有完整的音频分析、分段、导演、提示词、
逐段生成与拼接链路，数字人页面只做跳转。

## 新工作流（模式 2/3）

对齐用户提供的《Selflift参考生视频方便api1.0.json》：

```
UNETLoader → ModelAttentionBackend → LoraLoaderModelOnly
ResolutionSelector + LoadImage… → MiniMaxH3ReferenceToVideo（模式 2 额外接 ref_audios.ref_audio_0）
  ├─ positive → ConditioningZeroOut → negative
  └─ LATENT   → SelfLiftAvatarH3Sampler.latent_image
BasicScheduler →（H3SigmaRefiner）→ SelfLiftAvatarH3Sampler
  → VAEDecode（视频）+ VAEDecodeAudio（H3 生成的音轨）→ VHS_VideoCombine
```

与 MV 工作流的关键差异：

| | MV（模式 1） | 数字人（模式 2/3） |
| --- | --- | --- |
| 音频输入 | `LoadAudio → LTXVAudioVAEEncode → SolidMask(0) → SetLatentNoiseMask → LTXVConcatAVLatent` | 模式 2 只把参考音频接到 `ref_audios`；模式 3 完全不传音频 |
| SelfLift latent | 拼接后的 AV latent | Ref2VA 直接输出的 AV latent |
| 成片音轨 | 混入原始完整音轨 | 每段由 `VAEDecodeAudio` 解码 H3 生成的音轨，拼接后再封装 |
| 时长来源 | 音频分析 | 台词字数 / 语速（默认 5 字/秒）+ H3 合法帧数 `5+17k`（124–362 帧） |

实现位置：`backend/avatar/workflow.py`（构图）、`backend/avatar/job.py`（逐段生成、
take、拼接）、`backend/avatar/plan.py`（台词分段与提示词）。

## 台词分段（约 5 字/秒）

- 按 `。！？；…` 切句，按 `，、：` 拆超长句，再合并到目标段长附近（默认目标 8s / 最长 12s）。
- 每段秒数 = 字数 ÷ `chars_per_second`（默认 5.0），夹在 5.16s–最长段长之间；
  帧数对齐 H3 的 `5 + 17k`，范围 124–362 帧（24fps）。
- 段首尾相接，`start_frame` / `end_frame` / `frames` 全部落到项目里，可手工改台词或帧数
  （改台词会重新估算，并清空该段旧 take）。

## 提示词与系统提示词注入（占位）

- `backend/avatar/plan.py` 顶部 `SYSTEM_PROMPT_PLACEHOLDERS` 是**三种模式的系统提示词占位**，
  现在都是空字符串；注释里标了 `TODO(数字人)`。
- 注入逻辑已实现：`plan.build_messages()` 会按项目 `mode` 取对应提示词作为 system 消息；
  **非空**时 `/segments/{i}/prompt` 才会调用 LLM 扩写，**为空**时跳过 LLM，直接用内置
  确定性模板 `compose_prompt()`（保证页面永远能生成可提交的提示词）。
- 也可以不改代码，用 `GET/PATCH /avatar/api/prompts` 把提示词写进
  `data/avatar/system_prompts.json` 覆盖占位。
- 内置模板的语义：
  - 模式 2：`<Audio 1> is the canonical voice identity of S1…` + `<d>[Chinese] 台词</d>`；
  - 模式 3：不出现 `<Audio N>`，改写成“Voice identity and acting direction only, never spoken aloud: …”
    加同一段 `<d>` 台词块。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/avatar/api/health` | ComfyUI / ffmpeg / LLM 状态 |
| GET | `/avatar/api/options` | 模型/画幅/采样器下拉 + 默认生成参数 + 可选节点 |
| GET/PATCH | `/avatar/api/prompts` | 三种模式系统提示词（占位读取/写入） |
| GET/POST | `/avatar/api/projects` | 列表 / 创建（multipart，mode=2 可带 voice 文件） |
| GET/PATCH/DELETE | `/avatar/api/projects/{id}` | 读取 / 更新（name、mode、script、voice_description、语速、段长、generation）/ 删除 |
| POST/DELETE | `/avatar/api/projects/{id}/voice` | 上传 / 删除参考音频（模式 2） |
| POST/PATCH/DELETE | `/avatar/api/projects/{id}/refs[/{i}]` | 参考图增删改（role：performer/environment/appearance/subject/other） |
| POST | `/avatar/api/projects/{id}/plan` | 按台词重建分段 |
| PATCH | `/avatar/api/projects/{id}/segments/{i}` | 改台词 / 帧数 / 手写提示词 |
| POST | `/avatar/api/projects/{id}/segments/{i}/prompt` | 生成单段提示词（LLM 或内置模板） |
| POST | `/avatar/api/projects/{id}/prompts` | 生成全部提示词 |
| POST | `/avatar/api/projects/{id}/generate` | 启动任务（`only` / `force` / `generation`） |
| POST | `/avatar/api/projects/{id}/segments/{i}/regenerate` | 单段重生成 |
| POST | `/avatar/api/projects/{id}/cancel` | 中断 |
| GET | `/avatar/api/projects/{id}/run` | 任务快照（status/progress/message/logs） |
| POST/DELETE | `.../segments/{i}/takes/{take}[/select]` | 选片 / 删片 |
| POST | `/avatar/api/projects/{id}/assemble` | 用当前选中片段重新拼接（只跑 ffmpeg） |
| GET | `/avatar/api/projects/{id}/media/{path}` | 媒体（支持 Range） |
| GET | `/avatar/api/projects/{id}/download` | 下载成片 |

## 测试

```bash
python avatar_smoke_test.py   # 数字人：分段/提示词/注入/构图/上传/合成/媒体/下载
python smoke_test.py          # MV 回归：确认 MV 链路未被改动
```

`avatar_smoke_test.py` 不跑 ComfyUI 生成（用 ffmpeg 造片段验证拼接链路），
结束后清理临时数据目录，不碰真实项目。
