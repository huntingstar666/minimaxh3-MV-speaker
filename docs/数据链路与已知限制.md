# 数据链路与已知限制

这份文档给后续维护（包括 AI 辅助改动）一个“哪里会写、怎么写、哪里不能乱动”的索引。

## 1. 数据真源

- 每个项目一个目录：`data/projects/<id>/`，`project.json` 是唯一真源。
- 媒体文件在 `source.wav`、`refs/`、`takes/`、`final/`；`project.json` 只存索引与运行状态。
- `data/settings.json` 存全局配置（含 LLM key，不要提交、不要外发）。
- 写盘统一走 `backend/store.py`：
  - `save()`：同目录临时文件 + `replace` 原子替换；
  - `get()` / `save()` 都拿同一把按项目区分的 `RLock`；
  - `mutate(project_id, fn)`：在同一把锁内完成读-改-写，**只改部分字段时必须用它**，不要 `get()` 之后再 `save()` 整份。

## 2. 生成任务写盘规则

生成任务（`backend/jobs.py` 的 `JobRunner`）启动时加载一份 `project` 快照，运行中多次写盘。为避免覆盖用户同时在页面上的编辑：

- `_commit()` 只把任务负责的字段合并回磁盘上的最新项目：
  - 项目级：`generation`、`refs`（只回写 ComfyUI 上传名）、`final`；
  - 分段级：`status/error/output/started/finished/prompt_id/prompt_text/generation_frames/generation_seconds/fps/edit_frames`。
- 提示词字段（`final_prompt/prompt_source/prompt_key/prompt_warnings/prompt_overlays/prompt_stale`）：
  只有在磁盘上的正文仍等于本段“开始生成前”的基线时才写回；用户中途改过就保留用户版本。
- 运行状态 `run` 由 `_update()` 通过 `store.mutate()` 单独更新。
- 分段结构（起止帧）与任务快照不一致时（边界被改过 / 重新分析），本次任务的旧结果直接丢弃，不回写。

## 3. 结构性操作

重新分析、切点调整、切分、合并、删除项目会重建分段。这类操作：

1. 先 `runner.cancel()` 并 `runner.wait()` 等任务线程停下；
2. 由 `app._structural_lock` 串行化，避免两个请求交错；
3. 重新分析前如果已有提示词，自动备份 `project.json.bak-analyze-<时间>`（保留最近 5 份）。

## 4. 提示词字段生命周期

| 字段 | 含义 |
| --- | --- |
| `final_prompt` | 提示词正文（不含风格/滤镜/运镜前缀，除非是 AI 合并版本） |
| `prompt_key` | 输入指纹；简报/参考图/风格/运镜/模型变化 → 不匹配 → 自动提示词待重建 |
| `prompt_source` | `manual` / `llm` / `fallback`；`manual` 永远不被自动覆盖 |
| `prompt_overlays` | 这版正文“已合并”的风格/滤镜/运镜快照；匹配当前字段时不再追加前缀 |
| `prompt_stale` / `prompt_stale_reason` | 输入变了但正文还保留着，界面提示“可能已过期” |

- 展示 / 生成用提示词由 `prompts.effective_prompt()` 计算：未合并时把三个字段追加到正文最上面；已合并则原样使用。
- AI 重写（单段 / 全部）会把三个字段随素材包发给 LLM；返回文本作为新正文，并写 `prompt_overlays`。
- 输入变化只标记过期，不删除正文；「恢复自动」才会清空正文。

## 4.1 分段片段（take）

- 每次单段生成写一条新 take：`takes/seg_XXXX/t_000N.mp4` + `.jpg` 缩略图；`segment.takes[]` 记录元数据，`segment.selected_take` / `segment.output` 指向当前使用的一条。
- 新 take 自动选用；旧 take 保留，每段最多 10 条（星标与当前选中不删），超出删最旧的未选中项。
- 任务线程写回时按 `take_id` 与磁盘求并集，**不再整表覆盖**：生成期间用户删掉的片段不会复活，
  10 条上限真正生效；运行中手动换选也不会被任务结果打回。
- take 绑定 `segment_signature = start_frame-end_frame`：切点或重新分析后旧 take 不再展示/可选用，避免时长错位的片段被拼进成片。
- 选用/删除片段只改选择与文件，不触发生成；成片用 `final.take_signature` 判断选材是否变更，变更后由 `POST /api/projects/{id}/assemble` 用 ffmpeg 重新拼接（不跑 ComfyUI）。
- 旧项目首次读取时 `ensure_takes()` 把原来的 `clip.mp4` 懒迁移为 `t_0001`，缺失的缩略图在后台补生成。

## 5. 已知限制 / 剩余风险

1. **多标签页同时编辑同一项目**：服务端没有跨请求版本号，仍是最后写入者覆盖。建议一次只开一个编辑页面。
2. **重新分析必然重建分段**：现有提示词会失效；有确认弹窗与自动备份，但不会自动把旧提示词映射到新分段。
3. **`data/` 不进 git**：提示词、参考图、成片都不受版本管理；重要项目请自行复制 `data/projects/<id>/` 备份。`project.json.bak-*` 是部分覆盖操作前的兜底。
4. **生成中途 ComfyUI 崩溃/重启**：任务会标记失败，已完成的段保留，可续跑；未完成的段需要重新提交。
   卡在 `running` 的段会在任务异常退出时被改回 `failed`（以前会永久显示生成中、按钮一直禁用）。
5. **旧项目兼容**：没有 `prompt_text` 的项目无法从生成记录恢复提示词；没有 `prompt_overlays` 的项目会按“正文未合并”处理。
6. **LLM 结果不确定**：`prompt_key` 能避免输入未变时反复扩写，但换模型/参数后会重写。
7. **seam 逐窗生成、可断点续跑**：MV seam 已改为逐窗提交，每窗产物与 AV latent 落盘到
   `takes/_seam/`，manifest 记录计划指纹；第 k 窗失败只重跑缺口，计划不变时整条 0 次提交。
   改切点/提示词/模型/源音频会让指纹变化并全量重来；只改输出帧率不重跑生成。
   旧的一次提交保留为内部回退（ComfyUI 缺逐窗节点时）。
   seam 成片没有单段 take，过期判断改为看切点指纹；此时点「重新合成成片」会提示
   改用「重新生成全部」（已完成窗口会自动复用），而不是报「第 1 段缺少已选片段」。
   环境缺节点/模型时，先看 [首次安装与环境体检](首次安装与环境体检.md)。
8. **project.json 体积**：包含波形峰值、逐段信息与 take 元数据，长项目会到几百 KB～数 MB。
9. **前端状态非实时**：页面持有 `state.project`，其他客户端/API 直接改盘后需要刷新页面才能看到。
10. **可选节点自动跳过**：`sigma_shift` / `sigma_refiner` 现在按 ComfyUI `/object_info` 检测结果决定是否加进工作流；但模型名仍以设置面板为准。
11. **take 磁盘占用**：按 10 条/段上限，13 段大约 0.5～1GB；生成大量长段前注意磁盘空间。
12. **换选片段后必须重新合成**：选片不会自动改已有成片，需要在成片区点「重新合成成片」。
13. **首尾帧锚定**：仅模式 1 可用；每段独立、固定种子、首尾同图。默认 `plain` 单采（帧间差异 max 0.62）。`selflift` 走 `SelfLiftAvatarH3SamplerFix` + `highres_tiling=true`，自动关闭中间锚点：1MP 下 steps6/lowres0.5 max 3.26，steps10 → 1.28，steps10 + lowres0.75 + manual 2 块 → 0.96。`tiling_mode=auto` 在 0.4MP/1MP 会选 1 块（未真正分块）。首尾钉帧可选、默认关（拼接处精确但段内首尾 1 帧硬切）。2MP 全量未验收。**画幅必须与参考图实际比例一致**：16:9 → 1MP×32 = 1376×768，9:16 → 768×1376；比例填错不报错，只会在 `center_crop` 时裁掉画面。**提示词**：默认用固定模板 `plan.ANCHOR_DEFAULT_PROMPT`（`prompt_source=template`，音频分析/切点/拆分合并/改参数时自动写入），手改后按 `manual` 使用；**不要在提示词里写 `black` 等否定色词**——单采（`SamplerCustom`）会把背景压成纯黑（已实测：删掉 `black` 即恢复）。**已知限制**：单采与双采分开模型栈——单采使用参考工作流的 `Cobijada hybrid` + 官方 `dmad` LoRA@0.8 + int8 CLIP/VAE，并默认原图直进；双采使用 `fl2va int8` + nvfp4 CLIP + fp16 VAE + `DMAD LoRA@0.65` + SelfLift Fix 二采。切换单/双采会自动填入推荐栈；`custom_models=false` 时锚定生成强制使用推荐栈，用户手动改过模型（`custom_models=true`）则保留项目值；切回硬切会回到 Ref2VA 默认栈。
14. **双采步数分配**：总 NFE 来自 `BasicScheduler.steps`；`transition_step` 是低清评估次数，高清二采步数 = `steps - transition_step`。要求 `1 ≤ transition_step < steps`，高级生成参数折叠区实时显示分配、后端校验；参考默认 6 = 低清 4 + 高清 2。同一折叠区还暴露 `lowres_scale`、`upscaler_model`、`rho/w_min/w_max`、`tiling_axis` 与 `highres_tiling`（关闭 = 整帧），后端按 `generation` 实际写入节点。
15. **一键润色跳过规则**：`POST /prompts` 默认跳过 `prompt_source ∈ {llm, repair, manual}` 的段，返回 `skipped` / `generated`；需要全部重写时传 `{"force": true}`。运行本身始终不触发润色。
16. **二次采样开关**：硬切 / 尾帧接力（Ref2VA）默认双采；`ref_second_pass=false` 时 `backend/workflow.py::build` 与 `backend/avatar/workflow.py::build` 改走一次性 `SamplerCustom` 单采，且不再要求 `upscaler_model`。数字人接缝接续与混合接续在**模式 1（音频驱动）**下可用 `generation.seam_second_pass=true` 走 MV 同款逐窗二采（`MiniMaxH3TimelineSelfLiftSampler`）：混合时硬切窗（链首）与接缝链内窗都走同一张二采单窗图；需要放大器且 `1 ≤ transition_step < steps`。模式 2/3 的 seam 与 mixed 仍固定单采。双采参数（`transition_step` / `lowres_scale` / `upscaler_model` / `rho` / `w_min` / `w_max` / 分块）在 Ref2VA、锚定双采与模式 1 接缝/混合二采之间共用同一组字段。

## 6. 改动后的固定流程

```bash
git status && git diff      # 看改了什么
python tests/smoke_test.py  # 关键链路冒烟（独立临时数据，不碰真实项目）
```

全部通过后重启 `start.bat`，再刷新浏览器验证。

## 7. 2026-11-11 修复与维护约定

对应审查记录：[BUG审查-20261111.md](BUG审查-20261111.md)。

- **输出帧率必须贯穿到拼接**：`media.concat(..., fps=输出帧率)` 不能省。mixed 生成、mixed 重新合成、legacy seam 回退都已补 `fps`，否则 25/30fps 会被 `-frames:v` 按 24fps 截短。新增回归在 `tests/mixed_jobs_test.py` / `tests/mv_seam_test.py`。
- **数字人两种生成入口**：
  - 「开始生成」只补未完成/未选片的段（`pending_targets`）；
  - 「全部重新生成」发送 `force: true`，按当前表单参数重跑全部段；
  - 「单段重跑」发送 `only + force + generation`，会先把当前 generation 落库再跑。
- **锚定模板生命周期**：`stitch=anchor` 时后端写 `prompt_source=template`；切出 anchor 时只清自动模板并标 `prompt_stale`，手写/LLM 提示词保留。进入 anchor 仍由 `_fill_anchor_templates` 写模板。
- **放大器依赖按 stitch 判断**：hard/relay 看 `ref_second_pass`；seam/mixed 看 `seam_second_pass`（MV 与数字人模式 1），数字人模式 2/3 的 seam/mixed 视为单采。缺少 SelfLift 节点时 MV 允许降级单采，不因 `upscaler_model` 为空提前拦截。
- **接缝重叠口径**：数字人 `seam` 与 `mixed` 都读取 `generation.seam_overlap`；模式 1 不提供 5 帧（后端把 5 解释为默认 22）。`.h3avatar.zip` 的 `generation` 现在携带并恢复 `seam_overlap`。
- **成片过期口径**：MV `cuts_signature` 纳入行级 `overlap`（没有显式 overlap 时保持旧指纹兼容）；`final_stale_reason` 先比较 `stitch` / `output_fps` / `seam_overlap`；PATCH 项目 generation 命中这三个字段时立即标过期。
- **右栏脏标记**：`#f-stitch` / `#f-secondpass` / `#f-seam-overlap` 的 change 事件会走 `markFormDirty`，与设定弹窗共用未保存提示。
- **mixed 链起点**：`plan_windows` 的 base 用「累计边界差」，`plan_chain_windows` 用 `origin_frame/origin_edit` 锚定链绝对起点；25/30fps 下链起点严格等于 `round(累计 edit_frames × fps / 24)`，不再按段累积漂移。`split_long_chain` 同步使用该口径。
- **创作模式绑定项目**：只在 `POST /avatar/api/projects` 写入；`PATCH` 传不同 `mode` 直接 400，不再清空分段/素材。换模式必须新建作品。
- **设计层派生字段**：`design.route` 固定 `Ref2VA`；`design.audio_mode` 由模式派生（1=runtime / 2=reference / 3=generated）。两者只影响提示词腔调与 `.h3avatar.zip` 校验，不切换工作流；`ensure_design()` 读取旧数据、`update_design()` 写入时都会按模式纠正。
- **高级生成参数恢复默认**：只重置采样步数 / CFG / 采样器 / 调度器 / 模型栈 / 二采参数，保留当前单双采选择、画幅、清晰度、种子与段间模式；锚定双采按当前 `anchor_sampler` 套用对应推荐栈。

### 7.1 仍保留的已知限制

- 数字人 seam 续跑会检查 latent 文件存在（与 MV 对齐）；如果 ComfyUI 是远程地址，本地看不到 latent 路径时会保守地重新生成该窗，而不是复用。
