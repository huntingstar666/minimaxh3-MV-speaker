## 已确认事实（供核对）

- R2 实测：`30秒口播 · 手动测试`（`68ae98e69f9d`）四段的 take `prompt_text` 均为 **780 字模板**（`prompt_source=template`），说明**实际生成用的是默认模板**；但段 1 的 `segments[0].prompt` 在生成后被写成 **1111 字 Ref2VA LLM 提示词**（`prompt_source=llm`），属于显示/接口层错误，不是生成注入错误。
- R4 实测：同图、同种子、同 16:9，唯一变量为提示词时，含 `black` 的长提示词 → 黑背景；去掉 `black` → 正常。单采换用参考 JSON 的模型栈 + 原图直进 + 分离解码后，16:9 正常。
- R5 实测（`68ae98e69f9d`）：4 段各 1 条 take，取片卡片 104×79（含标签），点 ▶ 能打开 `#modal-take-preview`；工具栏在 anchor 下显示「一键填模板（可选）」「合成全片」，台词标签显示「模式 1 可选 · 不阻塞生成」。
- R5 语义确认：`backend/avatar/job.py` 生成时 anchor 只用 manual/模板，hard 只在提示词为空时补全；运行链路不会额外触发润色，因此「运行不包含润色」成立。
- R3 实测：段卡默认「预览 / 片段」高约 177px，切到「提示词」约 291px；四个 tab 切换正常，提示词/节拍相关操作会自动切到提示词 tab。
- R4/R8 实测（2026-11-09，`68ae98e69f9d` 第 1 段单采重跑）：ComfyUI 队列确认 UNET=`Cobijada_H3_Hybrid...int8_convrot`、CLIP=`qwen3vl_32b...int8_convrot`、VAE=`video_vae_int8_convrot`、LoRA=`官方仓库dmad...`@0.8、`SamplerCustom`；输出 `h3dh_00050-audio.mp4` 1376×768 / 8.71s / 209 帧，抽 2s 帧背景完整（非黑）。
- R8 复现细节：修复前同一任务在 sampling 阶段报 `httpx.ReadTimeout` 被判 failed，但 ComfyUI 队列仍在跑并最终 success；修复 `comfy.wait()` 后重跑全程 completed（run=completed，成片 31.2s，seg0 新增 take `t_0002`）。
- R9 现状：修复前段卡停在「生成中」；修复后重跑 4 段均为 completed。单测（替换 `store.mutate`）确认：失败时 `running/queued` → `failed + error`，`completed` 不动；取消时 `running` → `idle` 且清空 error。
- R10 实测（浏览器 DOM）：锚定单采 → `Cobijada + int8 CLIP/VAE + dmad@0.8 + preprocess=none`；切双采 → `fl2va int8 + nvfp4 CLIP + fp16 VAE + DMAD@0.65 + center_crop`，中间锚点恢复/备份正常；切硬切 → 回到 `fl2va int8 + DMAD@1.0` 并解锁模型控件；锚定卡新增可见的「模型栈」说明，模型/预处理控件在单双采下锁定。
