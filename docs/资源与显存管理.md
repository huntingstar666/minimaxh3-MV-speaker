# 资源 / 存储 / 显存管理

> 2026-11-05 落实。目标：磁盘不被临时文件和历史产物撑爆；生成前把显存让给 H3；排队/取消不误伤别人；上传有上限、生成前有磁盘余量检查。

## 一、配置项（`data/settings.json`）

```json
{
  "llm": {
    "unload_before_generation": true
  },
  "asr": {
    "unload_after_use": true
  },
  "storage": {
    "auto_cleanup": true,
    "temp_days": 1,
    "comfy_keep_days": 7,
    "comfy_keep_latest": 300,
    "min_free_gb": 2,
    "project_keep_days": 0
  },
  "comfy_free_after_job": false
}
```

- `llm.unload_before_generation`：开始 H3 生成前，如果是**本机 Ollama**，请求 `keep_alive=0s` 立即卸载模型（默认开）。远程 LLM 不动。
- `asr.unload_after_use`：开始生成前清空 Whisper 模型缓存并 `gc`/`empty_cache`（默认开）。
- `storage.auto_cleanup`：服务启动时后台做一次**安全清理**（临时目录、孤儿片段、过期临时目录、>50MB 日志轮转），不碰 ComfyUI output/input（默认开）。
- `storage.comfy_keep_days / comfy_keep_latest`：手动/脚本清理 ComfyUI 时，删除“超过天数 **或** 超过保留数量”的、且只属于我们前缀（`h3wb_` / `h3dh_`）的文件。
- `storage.min_free_gb`：生成前磁盘余量下限，低于则拒绝开始生成。
- `storage.project_keep_days`：>0 时按项目 `updated` 删除旧项目（默认 0=不删）。
- `comfy_free_after_job`：任务结束后调用 ComfyUI `/free` 卸载模型（默认关，避免连续生成反复加载）。

## 二、接口

```http
GET  /api/maintenance/usage
POST /api/maintenance/cleanup   {"dry_run": true}
```

`usage` 返回 project/hf-cache/日志大小、ComfyUI input/output/temp 大小、磁盘余量。
`cleanup` 默认 dry-run；`dry_run:false` 才真正删除，可选覆盖 `comfy_keep_days`、`comfy_keep_latest`、`temp_days`、`project_keep_days`。

## 三、CLI（推荐）

```powershell
cd h3-workbench
.venv\Scripts\python.exe tools\cleanup_storage.py --usage
.venv\Scripts\python.exe tools\cleanup_storage.py                          # 预览（安全项）
.venv\Scripts\python.exe tools\cleanup_storage.py --apply                  # 执行安全项
.venv\Scripts\python.exe tools\cleanup_storage.py --apply --comfy-days 7   # 额外清理我们的 ComfyUI 历史文件
```

脚本默认 dry-run；`--apply` 才删除。清理范围：
1. `takes/_norm`、`takes/_seam` 拼接临时目录；
2. 未被 `project.json` 引用的旧 take（生成中的项目自动跳过）；
3. `state/export-*`、`*.part/*.tmp/*.import`、`data/_tmp_avatar_voices` 等临时残留；
4. 可选：ComfyUI `output/input/temp` 中 `h3wb_*` / `h3dh_*` 且超过保留策略的文件；
5. 可选：`project_keep_days` 到期项目（默认不删）。

## 四、显存策略

1. **生成前**：`maintenance.ensure_disk_space` → `llm.unload_local`（本机 Ollama）→ `asr.unload()`；然后才进入 ComfyUI 生成。
2. **排队/取消**：GPU 锁改为 1 秒超时可取消等待；取消只对“属于自己的 prompt”调用 `cancel_prompt`，排队任务只置标记，不会误打断 ComfyUI 里别人的作业。
3. **任务结束**：可选 `comfy.free_memory()`（`comfy_free_after_job=true` 时）卸载 ComfyUI 模型。
4. **说明**：ComfyUI 自身仍会缓存已加载模型（这是它的加速策略）；如果同时用 Ollama/Whisper，默认策略已把它们在生成前释放。

## 五、上传与磁盘保护

- 参考图单文件 ≤ 50MB；参考/驱动音频 ≤ 200MB；`.h3avatar.zip` ≤ 2GB（另有 400 文件/包内上限）。
- 生成前检查 data 盘与 ComfyUI 盘剩余空间，低于 `min_free_gb` 直接报错，避免写到一半磁盘满。
- 音频时长仍限制为：参考音色 2 秒–10 分钟；驱动音频同。

## 六、实测记录（2026-11-05）

- 安全清理已执行：删除 `_norm/_seam` 临时目录 + 孤儿 take 共 **171MB / 22 项**；`projects` 从 **718MB → 555MB**。
- ComfyUI：`output` 16.85GB / 3,951 文件，`input` 4.21GB / 1,326 文件；其中**我们前缀只有 0.28GB**，其余来自本机其它 ComfyUI 工作流（AnimateDiff/Qwen/selflift 等）。因此自动清理**只清我们前缀**，共享目录的大头需要你/其它工具按自己的保留策略处理。
- 显存（RTX 5090 32GB）：检查时 `vram_free≈1.7GB`，Ollama `qwen3.5:9b` 占 6.6GB；现在每次生成前会先卸载 Ollama/Whisper。
- 项目 `project.json` 最大约 259KB（13 段提示词 + 1200 波形点），未发现异常膨胀。

## 七、P3 待优化：`comfy.view()` 的瞬时内存（已确认不是泄漏）

**结论：瞬时占用，写完即释放，不跨段累积，不是资源泄漏。**

- 生成路径：`comfy.view()` 把单段 mp4 读成 `bytes` → 写入 `takes/seg_xxxx/` → 该 bytes 失去引用被回收 → 处理下一段；同一时间只持有一段。
- 实测（2026-11-05，15 个项目）：
  - 普通分段 take：中位 **6.1MB**，当前最大 **7.7MB**；峰值约 10–20MB（含 httpx 缓冲）。
  - seam 整片模式例外：下载的是整条成片，实测 `takes/_seam/raw.mp4` 峰值约 **60MB**，瞬时上限约 60–100MB，同样是一次性的。
  - overlay 叠加时可能短暂多一份 buffer，峰值约为文件大小 ×2。
- 在本项目目标环境（32GB 内存 / RTX 5090）不构成风险；只有小内存机器 + seam 长片才值得改。
- 若后续要降到常数级内存：把 `comfy.view()` 改成流式 `GET /view` 分块写文件（seam 路径改动最小，普通 take 需要一并改 `_store_take` 的写入接口），需重新跑一轮真实生成回归，故本次未动。
