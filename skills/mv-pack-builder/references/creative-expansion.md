# 创意扩展与参考图缺口（技能核心原则）

**创意优先，素材后置。** 初始素材只是起点，不是创作边界。
Agent 在画面设计阶段要先把创意放开，再盘点“实现这个创意还缺什么参考图”，
然后向用户提出建议；用户采纳就补图，不采纳就按用户意见改。**绝不能因为用户一开始
只给了几张图，就自我审查、只做素材允许的保守方案。**

## 1. 原则

1. **先自由发散，再对照素材**：先想“这一段最想拍成什么”，不要先看手里有几张图。
2. **不静默降级**：因为缺参考图而放弃一个好点子，必须明确告诉用户缺什么、
   补了会有什么效果，让用户决定；不要偷偷换成平庸方案。
3. **补图建议要具体**：不是“再给点图”，而是“需要一张什么样的图、什么角色、
   用在哪一段、替代方案是什么、没有它画面会损失什么”。
4. **用户拥有最终决定权**：采纳 → 收图并更新设计/提示词；不采纳 → 按用户想法改，
   重新审阅。
5. **补图必须经用户同意**：不要擅自换人物、加角色、改场景；也不要未经允许调用
   生图工具。
6. **没有参考图也能拍**：H3 支持纯文本描述画面；可以用现有素材重新构图/打光/
   换角度，或在用户同意下用生图技能补图，或明确“这段不用参考图”。

## 2. 创意发散（画面设计第一步）

在写分镜表之前，先做：

- **整体概念 2–3 个方向**：一句话主题 + 视觉母题 + 色彩/光影 + 镜头气质；
  给用户选或混搭。
- **每段 1 个“最想拍”的画面**：如果完全不受素材限制，这一段最有记忆点的画面是什么？
  例如：雨夜天台逆光、镜面反射里的第二个人、从舞台背光走向镜头、产品从水中升起。
- **关键视觉 moment 3–5 个**：副歌/转折/结尾的高光镜头，先大胆设计。
- **创意与歌词/口播含义的对应**：每个点子要能解释“为什么这句歌词/这句话配这个画面”。

然后再进入素材盘点。创意阶段不写提示词、不因缺图删点子。

## 3. 素材盘点与缺口表

逐项检查每个创意元素需要什么参考：

| 创意元素 | 现有素材 | 缺口 | 需要用户补什么 | 优先级 | 没有它的替代方案 |
| --- | --- | --- | --- | --- | --- |
| 雨夜天台 | 只有卧室图 | 天台场景 | 一张雨夜霓虹天台（environment） | 高 | 改在卧室窗边，用投影/雨声暗示 |
| 第二套造型 | 只有一套衣服 | 服装 | 同一角色的黑裙造型（appearance） | 中 | 保持原服装，靠光影区分段落 |
| 关键道具（信/花） | 无 | 道具 | 道具图（subject） | 低 | 用空镜/手部动作暗示 |

“缺口”分三类：

1. **必须补**：不补就无法实现核心创意（人物身份/主场景/关键道具）；
2. **建议补**：补了明显更好，不补也能用替代方案；
3. **可选**：锦上添花。

对每个缺口给出 **具体建议**：

- 需要什么角色：`performer` / `environment` / `appearance` / `subject`；
- 图的内容要求：角度、景别、光线、背景、服装、是否露脸；
- 用在哪些段、会改变哪些提示词；
- 没有它时的 fallback（保持创意但改实现方式）。

## 4. 和用户确认的话术

> 我在第 4 段想到一个画面：人物站在雨夜天台边缘，霓虹从背后打过来。
> 这个点子需要一张「雨夜霓虹天台」的场景参考图（environment）。如果你有类似图，
> 发我我就加进参考图；如果没有，我也可以改成在现有卧室窗边拍，用蓝色霓虹投影
> 和雨声来暗示同样的情绪。你倾向哪种？

> 第 6 段副歌我想加一个「第二套黑裙造型」的反差，需要一张同一角色的黑裙参考图
> （appearance）。没有的话我就保留原服装，用顶光和慢动作制造反差。你看要不要补？

> 这段我建议加一个「手写信」道具特写，需要一张道具图（subject）。不补也可以，
> 我会用桌面空镜+手部动作带过。

## 5. 用户决策后的动作

### 采纳（用户提供/同意生成）

1. 拿到图片后**先确认角色**（performer/environment/appearance/subject），不要放错；
2. Agent 把图放进 `refs/` 并更新 manifest；如需用工作台预览，可用 `add_refs.py`：

   ```bash
   python scripts/add_refs.py --project-id <id> \
       --ref "D:\\img\\rooftop.png|environment|雨夜天台"
   ```

3. **更新设计**：在分镜表/design.json 记下用了哪张图、哪段引用；
4. **更新提示词**：`<Picture N>` 编号按最终参考图顺序重新核对，正文补上该图作用；
5. 重新走 Checkpoint B（画面审阅）和 C（提示词确认）。

### 不采纳（按用户想法改）

1. 记录用户意见（design.md 的审阅记录）；
2. 用现有素材重新设计：换构图/景别/光线/动作/道具替代/环境暗示；
3. **不要偷偷删掉创意**：在 design.md 写明“原创意 → 用户选择 → 最终方案”；
4. 重新审阅，通过后再写提示词。

## 6. 数字人 / MV 的补图例子

- MV：新场景（天台/地铁/花房）、第二套造型、关键道具、舞群/配角、风格参考图
  （mood board，不一定要用 role，可作 atmosphere 参考）。
- 数字人：办公室/咖啡厅/直播间背景、产品特写、图表/道具、第二套主播造型、
  反应镜头参考。
- 如果用户没有图又想要：可提议用 `local-image-gen` 技能生成参考图（需用户同意），
  或先用纯文字描述 + 现有图拍一版试片。

## 7. 完成标准（补充）

- [ ] 设计初稿至少给用户看过 2–3 个整体方向或关键画面选项；
- [ ] 每个创意缺口都有明确建议和 fallback，用户已做采纳/不采纳决定；
- [ ] 采纳的参考图已加入包/项目并标明 role，提示词编号已更新；
- [ ] 不采纳的创意已按用户意见改，并在 design.md 记录原方案与最终方案；
- [ ] 没有因为“用户最初素材少”而静默放弃高价值创意。
