# MV / 数字人设计工作流（技能核心）

这个技能不是“把音频和图片打进 zip”，而是：**先把整支片设计好，再产出完全设计好的包**。
交付包里每一段的简报、提示词、画面类型、运镜、参考图选择、切点都必须是 Agent 与用户
共同确认过的结果；用户导入后只需点“开始生成”。

## 0. 总原则

1. **先拆歌/拆稿，再设计画面，最后写提示词**；不要边打包边想。
2. **每段必须有明确任务**（建立人物 / 推进叙事 / 副歌情绪 / 转折 / 产品点 / 收尾）。
3. **每段必须有 brief + final_prompt**；不允许交付空提示词的“设计包”。
4. **必须与用户确认 3 次**：方向 → 分镜表 → 提示词与参数。不确认不进入下一步。
5. **参考图角色先确认**：`performer` 建议 1 张作为主身份锚点；同人不同角度/服装用
   `appearance`/`other`，配角/道具用 `subject`；所有角色合计最多 9 张，不是只能有 1 张参考图。
6. 所有画面遵守 H3 约束：单一连续镜头、无字幕/文字/水印、声音两段 N/A。

## 1. 阶段一：拆歌 / 拆稿

### MV（singing）

- 获取音频分析：BPM、段落（intro / verse / pre-chorus / chorus / bridge / outro）、
  能量变化、气口、歌词逐句时间。
- 这一步由 Agent 完成：用本地工具/脚本（ffprobe、音频分析、ASR、LRC/时间戳）读取素材；
  如果用户给了 LRC/逐句时间最好，没有就按歌词结构与时长设计切点，并在确认阶段给用户看表。
- 仅当 Agent 判断确有需要时，才把工作台 `analyze` 当内部工具（导入素材包 →
  `dump_design.py` 草稿）；**不要要求用户去工作台做分析**，也不把工作台当主流程。
- 分段规则：一般 3–15 秒（推荐 5–15）；特殊段落可放宽到 30 秒，但必须在设计审阅时
  与用户确认；不要切在字中间；长音/副歌可以保留完整乐句；段落交界优先落在低能量/气口。

### 数字人（speaking）

- 先选音频腔 A 音频驱动 / B 参考音色 / C 无音频参考（互斥，三选一；规则见
  [digital-human/README.md](digital-human/README.md)）。
- 按口播稿的**语义段落/句群/停顿**分段，一般 3–15 秒；特殊长句最多 30 秒且需用户确认；
  长句可拆，但不要断在词中间。
- 语速按 5 书面字/秒（含标点）预算；每段统计字数并报告“N 字，约 X 秒”。
- 重点句/产品点单独成段；每段一句话任务。
- 确定哪些句用 talking head（performance）、哪些句配 b-roll/空镜（environment）或
  氛围/反应镜头（atmosphere）。
- 设计动态图形节拍：触发词 / 入场 / 重音落定 / 可读停留 / 退场 / 干净恢复；
  同时只保留一组主信息，图形不遮挡脸/口/眼/手/产品/麦克风。
- 多人对话：按说话人拆音频/项目，不要试图让多人同框分别对口型。

### 分段表（必须产出）

| # | 起止(s) | 歌词/口播 | 能量 | 段落功能 | 视觉类型 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 01 | 0.0–11.8 | … | low | 建立人物/前奏 | performance | … |

## 2. 阶段二：画面设计

### 2.1 创意发散（先不管素材）

**先自由想，再对照素材。** 初始参考图不是创作边界：

- 整体概念给 2–3 个方向（一句话主题、视觉母题、色彩/光影、镜头气质），供用户选/混搭；
- 每段回答“如果完全不受素材限制，这里最想拍什么？”；
- 列出 3–5 个关键视觉 moment（副歌/转折/结尾的高光镜头）；
- 每个点子都要能解释与歌词/口播含义的对应。

详见 [creative-expansion.md](creative-expansion.md)。

### 2.2 素材盘点与补图建议

逐项核对创意需要什么参考图，做缺口表：

| 创意元素 | 现有素材 | 缺口 | 需要补什么（role/内容要求） | 优先级 | 没有它的替代方案 |
| --- | --- | --- | --- | --- | --- |
| 雨夜天台 | 只有卧室 | environment | 雨夜霓虹天台图 | 高 | 卧室窗边 + 投影/雨声 |
| 第二套造型 | 一套衣服 | appearance | 同角色黑裙图 | 中 | 保留原服装，靠光影区分 |
| 关键道具 | 无 | subject | 信件/花道具图 | 低 | 空镜/手部动作暗示 |

向用户提出**具体建议**：需要什么图、用在哪几段、补了会怎样、没有时的 fallback。
由用户决定：

- **采纳**：Agent 收图 → 确认 role → 加入 refs（可调用 `add_refs.py` 或直接放进
  `refs/` 并更新 manifest）→ 更新 design/ref_ids/`<Picture N>` → 重新审阅；
- **不采纳**：按用户想法改设计（换构图/光线/动作/道具替代），记录“原创意 → 用户选择
  → 最终方案”，不要静默删掉创意。

**不能因为用户最初素材少就限制创意发挥，也不能偷偷降级成平庸方案。**

### 2.3 叙事与视觉方向

- 一句话主题 + 角色弧线 + 场景/视觉母题 + 色彩/风格/滤镜 + 禁用元素。
- MV：把每段歌词翻译成一个**可拍摄的画面任务**，而不是重复“人物在唱歌”；
  可用动作、道具、环境变化、视线、光影、构图变化承载歌词含义。
- 数字人：固定中近景口播为基础，用 b-roll/空镜/产品特写打断单调；
  手势和动作按句意设计（强调、摊手、指产品、点头）。

### 镜头语言

- 能量 → 景别/运镜：低能量用固定/微移/中远景；中能量用横移/小弧线；高能量用推进/
  拉远/更强视差。相邻段避免同景别+同机位+同运镜。
- 每段写清：开场景别/机位、主体动作、镜头运动、结束构图、入场切法。
- 单个镜头内不要设计切镜/转场；跨段用硬切（或同机位 seam）。
- 参考图用 `@图N` 在素材要求/简报里指认；提示词里用 `<Picture N>`。

### 分镜设计表（用户确认用，也是 design.md 主体）

| # | 时间 | 歌词/台词 | 段意 | 景别/机位 | 运镜 | 主体动作 | 场景/道具 | 参考图 | 入场/风险 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 01 | 0–11.8 | … | 前奏建立 | 中景/正面 | 后移 | 静立演唱 | 浅蓝房间 | 图1/2/3 | opening/low |

## 2.5 画面设计审阅（Checkpoint B，强制）

**画面设计完成后先停在这里，不要直接写提示词。** 把以下材料交给用户审阅：

1. 方向：主题/角色/场景/视觉母题/风格滤镜/创意方向；
2. 分镜表：每段的时间、歌词/台词、段意、景别/机位/运镜、主体动作、场景/道具、参考图；
3. 切点表：为什么在这些位置切（乐句/气口/段落）；
4. 创意缺口表与补图建议：哪些图缺、建议补什么、补了有什么效果、fallback 是什么；
5. 需要放宽到 15–30 秒的特殊段落，单独标出并说明原因；
6. 可选：参考图截图/风格参考，帮助用户判断画面。

主动问用户：

- 故事/画面是否符合预期？哪一段不对？
- 景别、机位、动作、节奏有没有要改的？
- 有没有更大胆的想法/想加的镜头？我们可以评估补参考图；
- 缺口表里的补图建议，哪些采纳、哪些不采纳？不采纳时用哪个 fallback？
- 参考图用法/角色是否准确？场景/服装/道具有没有缺？
- 有没有不想出现的元素/镜头/姿势？
- 每个段落的画面任务是否清楚，还是太抽象？

把意见逐条落到 `design.json`/`design.md`，修改后**再次确认**。通过标准是用户明确
表示“可以/没问题/按这个做”；未通过不允许写 `final_prompt`、不允许打包。

审阅记录写进 design.md：

```text
审阅轮次：第 1 轮
创意方向：A 雨夜天台 / B 卧室投影 / C 镜面空间
用户意见：第 3 段镜头太远；副歌要看到抬手；不要出现文字
补图决策：采纳「雨夜天台」environment 图；不采纳「黑裙」→ 保留原服装用顶光
修改：段 3 改中近景+右前 30°；段 5 增加抬手动作；提示词禁止可读文字；更新 <Picture 4>
结论：已确认（2026-11-05）
```

## 3. 阶段三：逐段提示词

每段写两份内容：

1. `brief`：六行中文（画面任务 / 声音关系 / 开场构图 / 主体动作 / 镜头运动 / 结束构图）；
2. `final_prompt`：H3 六段英文结构（subject_definitions / summary / retention_analysis /
   detailed_description / overall_soundscape / non_diegetic_music）。

要求：

- **MV（singing）**：
  - `visual_type=performance` 必须有 `<Audio 1>`，写自然口型/停顿/呼吸；
  - `atmosphere` 闭口、不声明 Audio；`environment` 不出现人物；
  - 两个声音段必须字面 `N/A`；结尾必须有无字幕/水印声明；
- **数字人（speaking）**：
  - 按选定腔写 A/B/C：A/C 无 `<Audio N>`；B 定义 `<Audio 1>` + `audio reference` +
    `<Audio 1>: reference`；
  - 台词在 `<d>[中文] …</d>`；每段字数/目标语速已报告（5 字/秒）；
  - 动态图形按节拍写入 `detailed_description`，每个图形有入场/停留/退场/干净恢复；
  - 可见文案引号写死并声明字形/断行稳定；保护脸/口/眼/手/产品/麦克风；
  - 结构 lint：`python scripts/validate_digital_human_prompt.py PROMPT --audio-mode runtime|reference|generated`；
- `<Picture N>` 编号按本段实际用图顺序（1 开始），正文引用所有本段参考图；
- 提示词要落实 brief 的景别/机位/动作/运镜/结束构图，不要另加镜头；
- MV 的风格/滤镜/本段运镜字段由工作台在生成时追加；若正文里已经写了，包内用
  `prompt_overlays` 快照避免重复注入。

提示词规则：MV 见 [mv-prompt-format.md](mv-prompt-format.md)；数字人见
[digital-human/README.md](digital-human/README.md)，并只读选定的
`digital-human/voices/A|B|C-*.md`；通用摘要 [prompt-rules.md](prompt-rules.md)。

## 4. 阶段四：与用户确认（必须）

**Checkpoint A：方向**
- 主题/故事、角色、场景、风格/滤镜、画幅/帧率/拼接方式、参考图角色、是否出片。

**Checkpoint B：画面设计审阅（见 2.5）**
- 分镜表逐段审阅，听取意见并修改；通过后才写提示词。

**Checkpoint C：提示词与参数**
- 展示 2–3 个代表段的完整 `final_prompt`（至少开场、副歌/重点段、结尾）；
- 说明风险（多人、文字、长口播、seam、GPU 时间、>15s 段落）；
- 只有用户明确同意才进入出片。

> 任何一次修改都要回到对应 Checkpoint 重新确认，不要跳过。

## 5. 阶段五：落地（Agent 全流程）

**准备全部由 Agent 完成；用户面前的工作台只做最终预览/微调/出片。**
（Agent 可无头调用工作台的分析/导入接口作为工具，用户不参与；工作台本身仍是完整产品。）

1. Agent 自己读素材、分析音频/歌词、定分段，完成拆歌/拆稿与画面设计；
2. **Checkpoint B** 把分镜表交用户审阅并修改；
3. 审阅通过后 Agent 逐段写 `brief` + 提示词（MV `final_prompt`、数字人 `prompt`），
   按对应格式文档与校验器自检；
4. 生成 `manifest.json` / `.h3pack.zip` / `.h3avatar.zip` + `design.md`；
5. 严格校验（MV `validate_pack.py`，数字人 `validate_avatar_pack.py`）；
6. **Checkpoint C** 确认提示词/参数后，再把包交给用户在**工作台**预览、微调、生成；
   不要要求用户在工作台里重新分析、分段、写提示词。

> 可选：如果音频分析确实需要项目接口，Agent 可以无头调用工作台（导入素材→
> dump_design→分析）；这是 Agent 的工具使用，不是用户流程，也不把工作台当设计器。

数字人落地流程见 [digital-human/README.md](digital-human/README.md) 与
[avatar-package-format.md](avatar-package-format.md)。

## 6. 完成标准（缺一不可）

- [ ] 每个分段都有明确 `design_intent`（写进 design.md）与 brief；
- [ ] 设计初稿至少给用户看过 2–3 个整体方向或关键画面选项；
- [ ] 素材缺口表完整，每个缺口有具体建议与 fallback，用户已做采纳/不采纳决定；
- [ ] 采纳的参考图已加入包/项目并更新 `<Picture N>`/ref_ids；不采纳的创意已按用户
      意见改并记录原方案；
- [ ] 用户已完成画面设计审阅（Checkpoint B），意见已落实到设计并再次确认；
- [ ] 每个分段都有完整 `final_prompt`，六段结构/`[Shot 1]`/参考图编号正确；
- [ ] 数字人：已选 A/B/C 音频腔并只按对应 `voices/*.md` 写；A/C 无音频标签、
      B 有 `<Audio 1>` + audio reference + reference 保留行、C 有 voice card；
- [ ] 数字人：每段字数/目标语速已报告（5 字/秒）；动态图形每个都有入场/停留/退场/
      干净恢复，不遮挡脸/口/眼/手/产品/麦克风；
- [ ] `timeline.cuts_seconds` 与设计一致，切点不在字中间；一般每段 3–15 秒，
      超过 15 秒的特殊段落已单独说明并确认；
- [ ] 参考图角色正确（performer 1 张主身份；environment/appearance/subject 可多张，总≤9），
      提示词引用了本段所有参考图；
- [ ] style/filter/material_note/prompt_rule/generation 已按确认填写；
- [ ] 用户已确认分镜表、提示词与参数；出片已授权；
- [ ] `validate_pack.py --require-prompts --require-cuts` 全 PASS；
- [ ] design.md 与包一起交付。

## 7. design.json（apply_design.py 用）

```json
{
  "schema": "h3-mv-design",
  "version": 1,
  "mode": "singing",
  "style": "…", "filter": "…", "material_note": "…", "script": "…",
  "generation": {"output_fps": 24, "aspect_ratio": "9:16 (Portrait Widescreen)", "stitch": "hard"},
  "cuts_seconds": [11.8, 22.5],
  "segments": [
    {
      "index": 0,
      "design_intent": "前奏建立：空房间、人物静立等待",
      "visual_type": "performance",
      "brief": "画面任务：…\n声音关系：…\n开场构图：…\n主体动作：…\n镜头运动：…\n结束构图：…",
      "lyrics": "",
      "motion": "",
      "final_prompt": "subject_definitions:\n…\nsummary:\n…\nretention_analysis:\n…\ndetailed_description:\n[Shot 1] …\noverall_soundscape:\nN/A\nnon_diegetic_music:\nN/A"
    }
  ]
}
```

`design.json` 是 Agent 的工作草稿，不直接进包；最终包由 `apply_design.py --export-out`
或 Agent 手动生成的 manifest 产出。用户只在最后预览/微调。
